# Core

The Core contains the minimum current theory needed to regenerate Ordivon’s architecture and research direction for both present and materially stronger future Agents.

- [`intent.md`](intent.md) — why Ordivon is chosen, what scarce capability and freedom it protects, and why judgment cannot be reduced to process;
- [`foundations.md`](foundations.md) — working foundations, capability externalization, the acceleration test for durable constraints, and audited retention;
- [`stack.md`](stack.md) — the three-band architecture: flexible cognition, thin future-model-robust responsibility boundaries, and mature classical substrate;
- [`primitives.md`](primitives.md) — the minimal shared vocabulary needed to keep work, consequence, Effect, evidence, Tool drift, and owner-native facts distinct.

Detailed explanations belong in [`../knowledge/`](../knowledge/). Live alternatives and experiments belong in [`../research/`](../research/). Complete historical derivation remains recoverable from Git rather than occupying the active Core path.

A concept enters Core only when it is compact, stable across material model and Provider improvement, not already owned by a mature lower layer, non-bypassable for a real failure class, useful across materially different workloads, and beneficial after latency, maintenance, compatibility, cognitive, and control costs are counted.

Core therefore preserves **responsibilities rather than subsystem names**. Host, Harness, Runtime, Observation, Memory, World, Prime, Graph, multi-Agent organization, and similar implementation concepts may be useful without being permanent layers. Their current disposition is machine-bound in [`../research/computer-responsibility-map-v1.json`](../research/computer-responsibility-map-v1.json).
