# S6 Longitudinal Consequence Audit Contract — 2026-08-26

Status: **pre-frozen before detailed t1 outcome tracing of the selected cases**.

Truth role: Computing-owned cross-owner research audit design. It does not replace owner current truth, Atlas currentness, Host continuity, Runtime execution truth, or Book/Media authority.

## 1. Question

When a research Standing has already crossed into a default, interface, routine, guard, deletion/contraction, owner boundary, or ordinary first-look surface, what happens **later under natural Ordivon work**?

The audit tests the missing S6 layer:

```text
S5 environment / routine / interface / responsibility changed
→ natural elapsed use and system change
→ independently recoverable downstream consequence
```

The target is not whether the original result was elegant or whether its file still exists.

## 2. Ordivon-native method stack

Use the existing research ecology compositionally:

- **S0–S6 sedimentation coordinates** — separate persistence from consequence.
- **Owner-relative truth / currentness** — current owner facts must be resolved at the owner, not inferred from Host/Atlas/history.
- **Process Lineage + Git archaeology** — reconstruct what changed, when, and why without treating history as current authority.
- **PPD pressure discovery** — search for naturally occurring contradictions, consumption traces, stale carries, reopens and replacements already produced by Reality; do not manufacture failures or synthetic time.
- **Typed Standing + negative knowledge** — later demotion, replacement, no-use or `NO_CHANGE` are valid outcomes.
- **Generic Composition / mature-baseline subtraction** — do not attribute a later benefit to the standing if ordinary code evolution, provider changes, model improvement or unrelated owner work explains it equally well.
- **Origin-neutral assimilation** — external/provider evolution may strengthen or obsolete a local default; origin is provenance, not the capability boundary.
- **Challengeable environmentalization** — ask whether a default remained useful, became stale, was demoted/rebound, or escaped challenge.
- **Pressure-selection discipline** — prioritize cases with enough natural elapsed exposure and discriminating evidence; do not spend experiment budget on recent cases that cannot yet answer S6.

External mature methods are used only as solution content: longitudinal repository mining for temporal artifact evolution, within-case process tracing for mechanism/evidence chains, and post-deployment monitoring for unanticipated consequences under changing contexts. No Ordivon novelty is claimed for those methods.

## 3. Time-depth discipline

Natural exposure is classified at audit date 2026-08-26:

```text
T3 = >= 14 days
T2 = 7–13 days
T1 = 3–6 days
T0 = < 3 days
```

Primary S6 inference uses T2/T3 cases. T1/T0 may be recent controls but cannot establish long-horizon persistence.

## 4. Outcome vector — no scalar score

For each case recover independently:

1. **Survival / current habitation** — is the original placement still on the current path, migrated, superseded, deliberately deleted, or stranded?
2. **Natural consumption** — did later real Tasks/owners/Agents/tests actually encounter or use it without an audit-specific prompt?
3. **Benefit / harm / restraint** — did later work show reduced reconstruction/error/cost, improved safety/correctness/recovery, harmful friction/staleness, or a justified `NO_CHANGE`/non-action benefit?
4. **Stale carryover** — did the placement survive after its support conditions changed, causing incorrect current behavior or shadow authority?
5. **Challenge / demotion / rebind** — when Reality changed, was the placement correctly narrowed, replaced, removed or reopened while preserving history?
6. **Rediscovery / duplicate-work consequence** — did later work avoid a previously solved route, or did the same problem reappear because the standing was not naturally consumable?
7. **Maintenance / lifecycle burden** — what refresh, compatibility, provider, test, currentness or recovery cost did the placement create?

Possible vector-level conclusions include:

- `S6_POSITIVE_BOUNDED`
- `S6_NEGATIVE_STALE_OR_HARMFUL`
- `S6_JUSTIFIED_NO_CHANGE_OR_RESTRAINT`
- `S6_MIXED_REBIND_OR_DEMOTION`
- `S6_NOT_IDENTIFIED`
- `NOT_LONG_ENOUGH`

These are audit dispositions, not a global schema.

## 5. Evidence hierarchy for this audit

```text
L0 file/history existence
L1 later citation/reference only
L2 later owner/test/default path still depends on the placement
L3 independent later Task/consumer behavior changed consistently with it
L4 natural contradiction/rebind/removal demonstrates challengeability or stale-cost avoidance
L5 heterogeneous later consequences across multiple owners/consumers, with plausible rival explanations subtracted
```

`L0/L1` cannot establish S6 by themselves.

## 6. Counterfactual discipline

We generally do not observe the alternate timeline. Therefore:

- use natural pre/post or raw/current contrasts where already available;
- use later regressions/reopens/removals as negative controls;
- compare unchanged owners/surfaces where available;
- distinguish mechanism evidence from mere temporal correlation;
- retain `NOT_IDENTIFIED` when later success could equally be explained by unrelated model/provider/code change;
- do not fabricate an A/B by reverting production history solely to generate a desired S6 effect.

## 10. Admission ceilings

This audit does **not** establish:

- a universal organizational-learning metric;
- causal attribution from citation count;
- that all surviving defaults are beneficial;
- that deletion/no-change is failure;
- autonomous cumulative intelligence or a ratchet;
- month/year-scale effects from 7–13 day T2 exposure;
- a new S6 service, monitor, score, database, scheduler or global consumer registry.

The strongest possible result from this tranche is a bounded **one-to-two-week longitudinal consequence map** plus explicit longer-horizon reopen conditions.
