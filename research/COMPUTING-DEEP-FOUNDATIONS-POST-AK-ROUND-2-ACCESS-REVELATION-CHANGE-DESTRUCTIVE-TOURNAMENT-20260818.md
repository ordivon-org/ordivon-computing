Six rival explanations are tested.


Prediction: legal access operations need no semantic/model role beyond their scalar count.

## XA-M2 — Revelation is only an A-level environment assumption

```text
RevelationOrder
= part of EnvironmentAssumptions
```

Prediction: online/offline differences do not require an independent responsibility.

## XA-M3 — Access is part of B/I computational regime

```text
AccessModel
= admitted operation family / machine-memory-oracle model
```

Prediction: legal probes, passes, blocks and oracle calls are model parameters; B/I then state feasibility/power relative to them.

## XA-M4 — Query/update/change structure is semantic

```text
Query / Update / Dependency / Change
= C-level typed relations over computational representations/states
```

Prediction: correctness of change-sensitive reuse is semantic preservation, not a new primitive.

## XA-M5 — Incrementality is state retention

```text
IncrementalComputation
= J retention/reconstruction
```

Prediction: retaining old computational state is sufficient to explain valid incremental reuse.

## XA-M6 — independent Access/Revelation/Change responsibility

Prediction: after A/B/C/I/J subtraction, a nontrivial residual relation remains that cannot be expressed as a model/environment/semantic/retention composition.

The tournament attempts to falsify every rival.

# 3. Online paging: future revelation is constitutive, but not a new owner

Classical online paging gives the cleanest same-eventual-input pressure.

Sleator–Tarjan compare online paging rules with an offline rule that can use the full request sequence. The same eventual sequence can therefore induce different achievable guarantees depending on whether future requests are available to the algorithm.

Established:

```text
SameEventualRequestSequence
!= SameAvailableInformationDuringDecision

SameProblemFamily
!= SameAchievableGuaranteeAcrossRevelationRegimes

OfflineKnowledge
!= OnlineKnowledge
```

This falsifies XA-M1 in its strongest scalar form:

```text
RevelationStructure
!= resource amount by identity
```

But it does not establish XA-M6.

A already owns:

```text
EnvironmentAssumptions
InteractionInterfaceWhenPresent
```

B already owns a declared computational model and feasibility relation.

Therefore online paging is reconstructed as:

```text
A:
  future-information/revelation assumption

B:
  performance / resource / competitive guarantee under that model

C:
  request/action semantics when needed
```

Competitive ratio is not itself an Access primitive.

Verdict:

```text
OnlineRevelationPressure
= A + B composition
= no independent sibling
```

# 5. External-memory computation: access granularity precedes I/O counting, but B already has the slot

Aggarwal–Vitter explicitly model secondary storage as block transfers between internal and external memory and prove I/O bounds for sorting-related tasks.

This establishes an important anti-collapse law:

```text
AccessGranularity
!= NumberOfAccesses
```

Two models may permit the same abstract task and count an equal number of logical operations while assigning radically different I/O feasibility because the admitted transfer operation differs.

This initially looks like an X-A survivor.

However Round B already requires:

```text
ComputationalModel / AdmittedOperationFamily
```

including machine/memory/protocol/oracle assumptions before resource accounting.

Therefore:

```text
block-transfer legality / granularity
→ B computational model

I/O count / asymptotic transfer cost
→ B resource dimension

actual storage device truth
→ Hardware/Runtime
```

No new responsibility is required.

Verdict:

```text
AccessOperationFamily
is prior to ResourceCount
but both are already represented inside B's model-relative feasibility responsibility.
```

This falsifies XA-M1 but supports XA-M3.

# 6. Cell-probe and dynamic data structures: update/query interface is semantic; probes are resources

Fredman–Saks define dynamic data-structure problems around representations that support modifications and queries, then analyze operation costs in the cell-probe model.

The hostile separation is:

```text
UpdateSemantics
!= QuerySemantics
!= ProbeCost
```

A dynamic data structure cannot be specified merely by saying `N probes`.
One must know what an update means, what a query asks, what representation is maintained, and what memory access operation the model admits.

Factorization:

```text
C:
  representation
  update relation
  query relation
  correctness/equivalence

B:
  cell/probe model
  word/cell parameters
  update/query cost
  preprocessing/space/time tradeoffs

I / Algorithmics:
  model-relative existence/nonexistence/lower-bound claims

A:
  external operation sequence assumptions when order/adversary matters
```

Established:

```text
DynamicDataStructure
!= PersistentStateByIdentity

DynamicDataStructure
!= OnlineAlgorithmByIdentity

DataStructureInterface
!= AccessCost
```

J does not own dynamic data structures merely because they retain state.
J becomes relevant only to what retained auxiliary state survives some declared lifetime/disruption boundary.

Verdict:

```text
DynamicAccessPressure
= C + B + I/Algorithmics (+ A when order matters)
```

Again no independent X-A remainder.

# 9. Preprocessing / advice separation

Data-structure and query models often separate preprocessing from query/update work.

This must not be collapsed into nonuniform advice.

```text
InstanceDependentPreprocessing
!= LengthDependentNonuniformAdvice
```

Preprocessing can inspect the particular input instance and construct auxiliary state.
Advice may depend only on a declared nonuniform index such as input length/model family.

Factorization:

```text
B:
  preprocessing time/space and amortization accounting

C:
  representation produced by preprocessing and its query semantics

J:
  retained auxiliary state if lifetime/reconstruction is material

I:
  nonuniform advice/power only where genuine advice is admitted
```

Therefore a separate `Preprocessing` primitive is rejected.

# 10. Incremental view maintenance: change is semantic input, not state retention by itself

Gupta–Mumick–Subrahmanian present algorithms that compute changes to materialized views in response to insertions, deletions and updates in base relations.

This directly falsifies XA-M5:

```text
RetainedMaterializedView
!= ValidIncrementalMaintenanceByItself
```

A retained old view is not enough. One needs:

```text
base-relation change semantics
view-definition semantics
derivation/dependency structure where material
incremental maintenance transformation
correctness relation between new base state and new view
```

Factorization:

```text
C:
  source/update/view semantics
  derivation/dependency relation
  preservation/correctness of delta transformation

J:
  retained materialized state
  retention/reconstruction if relevant

B:
  incremental vs from-scratch work/space/I/O

A:
  arrival/sequence of external changes
```

Established:

```text
RetainedState
!= IncrementalValidity

ChangeMagnitude
!= RecomputeCostWithoutDependency/AlgorithmSemantics
```

This is the first major reason not to let J absorb X-A.

But it still does not establish XA-M6 because C has the exact semantic-relation slot needed.

The most important architectural result is that B is not merely a vector of scalar resource counters.


When relevant it includes:


Only after the model is fixed do resource counts become meaningful.


# 17. Cross-owner subtraction

## Runtime

Concrete execution schedules, cache instances, process state, materialization, retry and actual lifecycle remain Runtime truth.

## Network

Actual data transport and deployed communication remain Network truth. Abstract communication/query access costs remain Computing-level model claims.

## World

Actual environmental changes are World facts. Computing only states what change/revelation assumptions enter the computational claim.

## Harness

Agent context/tool/run/orchestration state remains Harness-owned. Abstract query/access/update/reuse relations can be Computing-level only after subtraction.

## Hardware

Physical memory hierarchy/device truth remains Hardware/Runtime. Abstract external-memory/cell-probe models are computational models rather than device facts.

## Mathematics

Lower-bound theorem truth remains Mathematics in general; computational ownership concerns the typed application to a declared model/problem/resource regime.

## Specialized Algorithmics owner

An independent current Ordivon Algorithmics residual reranking at `task:algorithmics-foundation-algf0-20260818` revision 6 separately concluded that sublinear/streaming/local computation primarily enriches the declared Algorithmics regime with information-access/pass/query/sketch structure and did not justify a new Algorithmics primitive.

```text
and
```
