# 3. Major omitted / underrepresented continents found outside the inherited U-A→U-H partition

## X-A — Computational Access / Revelation / Change Regimes

This is broader and more primitive than `Online / Streaming` alone.

It includes:

```text
offline vs online input revelation
streaming / one-pass access
random-access vs sequential-access input
external-memory block access
query / oracle / probe access
property-testing / sublinear observation
dynamic update/query interfaces
preprocessing vs query-time access
incremental / self-adjusting recomputation
materialized-view maintenance
change propagation / dependency reuse
```

The central question is:

```text
Is access/revelation/change structure merely a collection of
B resource dimensions + A environment assumptions + I oracle power + J retained state,
or is there an irreducible computational burden specifying
what information may become available, when, through which admissible observation/update relation,
and which prior computation remains reusable after change?
```

This continent was not isolated in the closeout as one architectural pressure family.

### Minimal anti-collapse pressures

```text
SameProblem + SameFinalInput
!= SameAchievablePerformance under different revelation schedules

SameResourceBudget
!= SameFeasibility under different access models

OfflineAccess
!= OnlineAccess

RandomAccess
!= OnePassStreamingAccess

StaticEvaluation
!= DynamicUpdateQueryMaintenance

FreshRecomputation
!= NecessaryUpdatedComputation

StoredPriorState
!= SufficientIncrementalReusability

InputAvailability
!= ResourceConsumption

OracleAnswerAvailability
!= PhysicalTransport
```

### Direct attack targets

```text
A: is revelation order only an EnvironmentAssumption?
B: are probes/passes/I/O only resource counters, or is access topology prior to resource measurement?
I: is oracle/query availability simply relative computational power, or does it require a separate admissible-access contract?
J: does retained state become computationally relevant only through dependency/change relations?
C: are dynamic dependency and admissible-update relations purely semantic relations?
```

This is the strongest newly reconstructed candidate continent.

## X-B — Reliable / Fault-Tolerant Computation Under Faulty Components

The inherited closeout lists generic fault tolerance/error correction only as a partial cross-layer topic. That understates its architectural reach.

The tradition from unreliable Boolean components through self-stabilization and quantum fault tolerance demonstrates a recurrent form:

```text

+
component/noise/fault model
+
redundant or encoded realization
+
detection/masking/correction/recovery structure
+

+

```

Key pressure:

```text
CorrectAbstractComputation
!= ReliableRealizationUnderFaults

PhysicalFidelity
!= FaultToleranceArchitecture

FailureProbability
!= ApproximationErrorMagnitude

Recovery
!= FaultMasking

Redundancy
!= CodingOnly

CoordinationFailureModel
!= GenericComponentFaultModel
```

Potential ownership currently fragments across:

```text
D error/validation
F stochastic faults/risk
G distributed failure/progress
H realization fidelity
J recovery/reconstruction

```

A future destructive round could therefore either admit a genuine resilience responsibility or provide strong consolidation evidence by proving that no independent remainder survives.

Classification here: `VERY HIGH INFORMATION`, but second to X-A because owner/refactor entanglement is heavier.

# 6. Owner subtraction

## Runtime

Runtime owns concrete execution occurrences, process/job/attempt lifecycle, scheduling realization, retries/resume, environment materialization and runtime state truth.

Computing may own abstract access, temporal, resource, solvability and change-propagation relations without owning the concrete execution event.

## Harness

Harness owns Agent task/run/tool/context/orchestration structures and operational adaptation loops. Computing may analyze the underlying algorithmic/access/resource relations only after subtracting those operational identities.

## Network

Network owns actual inter-locus transport, reachability, forwarding, congestion/queueing and deployed communication realization. Computing may own abstract communication/query/access complexity.

## World

World owns physical dynamics, causation, measurement, actual time and biological/chemical reality. Computing owns only a computational realization/grounding relation to those realities.

## Human

Human owns cognition, perception, learning and human practical/mental structures. Computational learning/adaptation must be separated from human learning.

## Security

Security owns authority, confidentiality, integrity, adversarial compromise and trust goals. Computing may own abstract hardness, indistinguishability or protocol-computation relations only after those goals are subtracted.

## Hardware

Hardware owns concrete circuits/devices/memory technologies and architecture facts. Computing may own abstract machine/access/circuit models and resource relations.

## Mathematics

Mathematics owns theorem truth and generic mathematical structure. Computing consumes those structures when indexed to computational problems, models, access rules, resources, semantics or realizations.

## Media

Media owns expression/perception/media-specific semantics. Token/string/media representations are not automatically Computing primitives.

## Existing Computing-descendant owner lines

Current Ordivon continuity also contains specialized computational semantics / computational possibility / algorithmics research. Those are treated as subtraction warnings: a broad Computing tournament must not duplicate an already-specialized semantic-owner claim merely because the same formal vocabulary appears here.

# 8. Why X-A wins over Real-Time and Proof

X-A has four advantages.

First, it attacks more of the current architecture simultaneously:

```text
A + B + I + J + C
```

Second, it has unusually clean minimal counterexamples:

```text
same task + same eventual input + different revelation schedule
same abstract task + different allowed probes
same final state + different update/query history
same new answer + from-scratch vs dependency-aware incremental recomputation
```

Third, it has lower owner contamination than cyber-physical computation, where physical-time and control-loop truth immediately crosses World/Runtime/Hardware.

Fourth, either outcome is high-value:

```text
if an irreducible Access/Revelation/Change burden survives
→ architecture expansion / refactor

if every case reduces cleanly into A/B/I/J/C
→ strong new consolidation evidence toward whole-domain closure
```

Therefore this route has unusually high expected information gain independent of whether it produces a new sibling.
