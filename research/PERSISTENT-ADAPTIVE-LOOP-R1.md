# Persistent Adaptive Loop R1 — P1–P5 Recursive Improvement Falsification

Status: **closed**. This is a Computing research conclusion, not a new Ordivon architecture layer.

Machine record: [`persistent-adaptive-loop-r1.json`](persistent-adaptive-loop-r1.json).

## 1. Question

R0 separated:

```text
ExecutionEvidence
→ DomainOutcome
→ WorldModelDelta
→ PersistentChange
→ RecursiveImprovementEvidence
→ AutonomousPressureSelection
```

R1 attacks one specific shortcut in that ladder:

> **Does a change that survives into the next loop actually improve the next loop?**

Five materially different Persistent Changes were tested. The round intentionally allows negative results. A useful checkpoint, a fast network path, a behavior-changing prompt, an exact reducer, or a good creative prior does not receive L4 credit merely because it exists.

## 2. Result in one table

| Phase | Persistent Change | Later test | Result | L4? |
|---|---|---|---|---|
| P1 Host | durable semantic checkpoint | fresh continuation | useful only for irreducible task-private commitment/identity; owner-reconstructable cases gain no correctness | **No** — scoped L3 value |
| P2 Workstation | native-a/native-b scoped HTTPS paths | Finance/World/Provider semantic consumers | real option/latency value, but ambient already completes all tested useful work; OKX fails on scoped paths | **No** |
| P3 Game | responsibility ownership/feedback prompt prior | 8 paired held-out live DeepSeek Runs | behavior changes, but rescue objective remains 0/2 in every rescue pair; oscillation is worse | **No** |
| P4 Security | deterministic AE3-C/EC0 evidence reduction | six unseen sensor-history structures | raw 0/12 → projection 10/12 with fewer tokens, but two identical model-consumption errors remain | **No under reliable gate** |
| P5 Web | render-review prior from ordinary Web/Studio production | new ordinary About/Colophon surfaces | finds source/build-invisible desktop encounter residual; local fix passes 228/228 and controls remain byte-identical | **Yes, scoped production mechanics** |

The round therefore produces **one narrow positive L4 result and four different falsifiers of overly generous L4 attribution**.

## 3. P1 — persistence utility is conditional on irreducibility

Host was tested against a strong baseline that always receives the same current owner evidence.

### Owner-reconstructable cases

Six cases, two replicas per treatment:

```text
fresh owner evidence       12 / 12 correct
checkpoint + owner evidence 12 / 12 correct
```

The checkpoint treatment used roughly 9k more prompt tokens and added **zero correctness**. It did not become harmful because the Agent correctly revalidated stale Runtime/Git hints, but it also did not earn semantic value.

### Task-private cases

A second treatment used facts that current repository/provider documentation cannot reconstruct:

- an exact participant-selected experiment variant;
- an exact unresolved provider request identity;
- an exact participant-approved deletion boundary.

Here the fresh baseline correctly refused to guess in 6/6 cases, while checkpoint-assisted continuation made exact productive progress in 6/6.

The retained law is smaller than “memory helps”:

```text
stored state != useful persistence

owner-reconstructable state
→ re-observe

irreducible task-private commitment / unresolved identity
→ persist
```

Host therefore earns its semantic continuity boundary without earning a generic Memory mandate. This is still L3 continuation value; the experiment does not show that the checkpoint improves a later *improvement process* beyond safe continuation.

Canonical Host: `94d980a8b331df027557ea4e7ea45d53eb4c9bcc`.

## 4. P2 — capability is not useful-work expansion

Workstation's scoped `native-a` / `native-b` HTTPS paths were tested as actual downstream consumer paths, not as “two more routes.”

### Finance / OKX

```text
ambient   3 / 3 semantic ticker success
native-a  0 / 3
native-b  0 / 3
```

### World / OpenAlex

All paths succeed, but median latency changes:

```text
ambient   3611 ms
native-a  1742 ms
native-b  1599 ms
```

### DeepSeek service reachability

All paths succeed:

```text
ambient   2071 ms
native-a   504 ms
native-b   496 ms
```

The scoped paths therefore have real **option value** and **performance value**. They also cost two dedicated services plus exact current digest/destination qualification. In the current world, however, they do not expand reachable useful work over ambient.

The retained law is:

```text
available capability != expanded useful work
```

Do not synthesize an ambient failure merely to turn an option into an L4 success. Wait for a real failure or workload in which the retained capability changes what Ordivon can actually do.

Canonical Workstation: `4480ca9bdf3ee59a7906d08136a1e7289548535a`.

## 5. P3 — behavior change is not objective transfer

Game tested one existing learned prompt prior rather than inventing a new planner. The current DeepSeek prompt tells Actors to prioritize assigned responsibility and to avoid blindly repeating a failed responsibility action. The baseline used the same Game World, Candidates, evaluator, Provider implementation, profiles, seeds and six-Turn bound, removing only those two responsibility-specific prompt paragraphs at request time.

Eight paired live Runs completed. All were owner-verified and exposed zero hidden references.

The prior **did change choices**. That is not enough.

Across the four rescue pairs:

```text
treatment rescue objective progress: 0, 0, 0, 0
baseline  rescue objective progress: 0, 0, 0, 0
```

Aggregate movement oscillation was also higher under treatment (`25` vs `9`). More importantly, one treatment trace binds custody of Navigator Sato and later still chooses a non-extraction `responsibility:advance` move to Power Console.

So:

```text
model-visible prior
!=
model-realized policy
!=
held-out objective transfer
```

The prior may remain Game-local product prompt craft. R1 does **not** promote it as an RSI prior and does not respond by compiling the desired answer into a planner.

Canonical Game: `82e29e3119e692a169f9e9eadf27b1247f0eefa7`.

## 6. P4 — deterministic projection is not deterministic cognition

Security already had a real failure → repair lineage:

```text
AE3-B raw history
→ model aggregation instability
→ AE3-C / EC0 exact deterministic reduction
```

R1 moved away from the original A/B fixture and generated six unseen sensor-history structures. Two live replicas per cell compared raw history against the exact reducer projection.

Final valid campaign:

```text
raw history          0 / 12 correct
                      11,388 prompt tokens

derived projection 10 / 12 correct
                       7,884 prompt tokens
```

This is strong transfer evidence. But the predeclared reliable gate was 12/12. It failed.

Both residual errors occurred on the same held-out `h2` case. The deterministic projection contained:

```text
sourceBMatches = 2
```

and the model reported:

```text
sourceBMatches = 6
```

in two independent replicas.

Therefore:

```text
exact computation
→ exact projection
!=
exact model consumption
```

This supports externalizing deterministic computation. It does **not** justify a Trust/Reputation system, a generic EvidenceReducer service, or reliable L4 attribution under the stated gate.

Security owner tree remains unchanged at `7f257ce33b7497fb62e109da526ee81a859ad2b9`; accepted Runtime run is `job-019ffb26-f747-7371-8ab4-651fc818b6a3`.

## 7. P5 — one scoped L4 transfer survived

Web/Studio had already earned a production prior:

> when expression/layout matters, inspect the exact rendered artifact; source code, typecheck, build and mechanical browser success do not substitute for rendered semantic judgment.

R1 transferred that prior to two ordinary Web surfaces outside the existing benchmark set: `/about` and `/colophon`.

Baseline mechanical checks were green. Exact browser pixels exposed a residual on `/about` desktop: at `1440×1000`, the first viewport carried the large thesis heading but not the introductory explanatory paragraph. `/about` mobile and both `/colophon` controls did not share that first-viewport structure.

A local candidate changed only desktop About hero spacing/scale. No content, fact, component, mobile rule or control route changed.

After the change:

- About desktop pixels changed;
- About mobile pixels were byte-identical;
- Colophon desktop/mobile pixels were byte-identical;
- the current rewritten browser-review implementation reproduced the exact same treatment/control PNG digests;
- Web full gate passed **228/228 Playwright tests**, plus build/type/lint/publication/design/accessibility.

This is enough for a narrow L4 claim:

```text
earlier production prior
→ later independent ordinary surface
→ detects a real residual missed by source/build gates
→ drives bounded correction
→ owner gate + exact controls verify it
```

It still says nothing about human preference, comprehension, trust or beauty. Those remain `UNKNOWN` without human evidence.

Canonical Web: `ee1232689f1c5d48f884d0c9c83517fe5c471332`.

## 8. Revised L4 admission rule

R1 suggests a stricter admission boundary. A Persistent Change should receive recursive-improvement credit only when the claimed scope contains, where applicable:

```text
later independent consumption / held-out workload
+ owner-native outcome improvement relevant to the mechanism
+ no hidden answer compilation or evaluator leakage
+ explicit transfer/scope boundary
+ recurring maintenance / fragility / cost accounting
+ retained negative and residual evidence
```

This is not a mandatory Protocol object and not one universal scalar. Different domains retain different outcomes.

The important update is conceptual:

> **L3 is a candidate for future value, not evidence of L4.**

## 9. Five new cross-project laws

R1 adds five compact distinctions to the PAL research lens:

```text
stored state
!= useful persistence

available capability
!= expanded useful work

behavior change
!= held-out objective transfer

deterministic projection
!= deterministic cognition

rendered encounter evidence
!= human response
```

The sixth law ties them together:

```text
Persistent Change
!= Recursive Improvement Evidence
```

until a later loop actually consumes and validates the change.

## 10. Architecture disposition

P1–P5 do **not** justify:

- WML v3;
- a PAL/RSI controller;
- a universal improvement score;
- a global owner-state registry;
- a generic Memory layer;
- a network expansion policy;
- a Game planner that compiles successful behavior;
- a shared EvidenceReducer service;
- a visual/human-response score.

WML v2 and current owner-native evidence can already express every result. The system change is a **research admission standard**, not a new runtime component.

L5 also remains untouched. This round was deliberately selected through explicit research judgment. It is not evidence that autonomous next-problem discovery now works, and it does not reverse the negative C6 owner-pressure result.

## 11. What should happen next

There is no need for an immediate P6 mega-layer. Reopen each line only under natural pressure:

- Host when a real cross-session task can test whether irreducible semantic continuity improves a later improvement outcome, not merely safe continuation;
- Workstation when ambient genuinely fails or a new consumer is uniquely enabled by a retained scoped path;
- Game on a materially different held-out World/model or a predeclared full-horizon objective transfer test;
- Security when exact deterministic evidence can be consumed without the residual transcription/interpretation error, or a second domain independently demands the same boundary;
- Web/Studio when another ordinary production independently consumes render-review; human-response claims still require human evidence;
- autonomous problem selection only when a materially different owner-generated pressure signal or representation appears. Do not rerun C6 with cosmetic prompt changes.

R1 therefore closes with a narrower and stronger RSI model: **Ordivon already knows how to preserve and recursively reform some changes; it is now learning to refuse recursive-improvement credit until the next world actually cashes the check.**
