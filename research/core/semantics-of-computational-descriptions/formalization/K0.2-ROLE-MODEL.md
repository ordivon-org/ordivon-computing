# Minimal Formal Kernel K0.2 — Role Model

Status: **PROVISIONAL / DISPOSABLE**.

K0.2 is not an SCD calculus and not a universal semantics. It is a thin coordination interface for stating cross-framework semantic obligations without erasing owner, scope or dependency distinctions.

## Flat notation

The current candidate vocabulary is:

- `D` — Description.
- `Σ` — SemanticEnvironment; compact notation preserving distinct projections to SemanticContract `K` and SemanticModel `M`, plus any framework-relevant signature/alphabet/interface/observation surface.
- `ρ` — external/shared ComputationalDescriptionRole admission witness or judgment input.
- `φ` — typed SemanticClaim.
- `v` — typed Variation between semantic situations.
- `μ` — framework-supplied typed SemanticCorrespondence witness family.
- `Δ` — typed support/dependency set, including references to external owner-native authority where relevant.

Artifact/carrier identity stays outside the semantic kernel as provenance/navigation. Context remains provisionally a specialization of `v`. SemanticStanding remains derived.

## Preferred role decomposition

Instead of treating the seven elements as peers, reason using four roles:

```text
Situation S = (ρ ⊢ D @ Σ)
Claim     φ
Change    χ = (v, μ)
Support   Δ
```

with the derived standing judgment:

```text
Stand(φ | S, Δ)
```

A source/target change is written schematically as:

```text
(Ds, Σs) -v-> (Dt, Σt)
φs       -μ-> φt      # only when a target correspondence is asserted
```

`μ` is not a universal claim-to-claim function. Frameworks may instantiate it with state/behaviour simulations, abstraction/concretization relations, refinement embeddings, sentence/model translations, observation correspondences, or another justified semantic relation.

## Static standing vs standing transition

Static standing is currently treated minimally as a derived judgment such as:

- stands;
- fails;
- unresolved.

Cross-variation standing transitions may be described as:

- preserved;
- weakened;
- strengthened;
- reinterpreted;
- invalidated;
- unresolved.

These are not one universal project status enum.

## Core non-inferences

- Same Artifact does not imply same Description semantics.
- Same Description does not imply same standing under changed `Σ`.
- Existence of `v` does not imply preservation.
- Existence of `μ` does not imply a valid preservation proof.
- Successful execution does not imply semantic preservation.
- Network availability does not imply semantic transport validity, and semantic transport validity does not imply Network availability.
- Current Host continuity does not imply semantic currentness.

## Why no K0.3 yet

The canonical corpus and cross-framework mappings have not forced another universal primitive. Framework-specific structure should remain inside `Σ` / `μ` unless a hostile case proves that doing so destroys clarity, falsifiability, owner separation or semantic expressiveness.

Open pressure points:

- whether `μ` should remain a first-class interface slot;
- whether `Σ` requires a universally explicit Signature/Vocabulary/Interface projection;
- whether Description identity or lineage eventually becomes first-class;
- whether SemanticStanding remains derivable in multi-branch/multi-environment cases.
