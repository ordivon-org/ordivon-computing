# ANC-MULTI-001 — Multi-Agent Branch, Join, and Artifact Coordination

## Status

Deferred at **M4** after Computer P4 live evidence. The minimum two-participant branch/Artifact/Verification/Join workload is mechanically expressible with current Host primitives, while a strong two-call independent-participant treatment did not achieve the pre-registered strict holdout win over sequential single-participant reflection. No Multi-Agent framework is admitted. Reopen only for a materially different workload or concrete consumer that exposes a repeated missing responsibility.

## Question

When does more than one independent Agent participant create verified information or work that a single Agent plus an independent verifier cannot produce at equal or lower cost, while keeping responsibility, Effects, Artifacts, recovery, and Join semantics explicit?

## Strong baseline

The baseline is not a weak single-pass Agent. It is one capable Agent with the same evidence and Tool authority, plus an independent verifier/evaluator and ordinary Host/Runtime recovery. If that baseline matches independent branches, there is no demonstrated Multi-Agent substrate requirement.

## Minimum workload

Freeze one Goal whose solution naturally admits two independent hypotheses or work branches. Compare:

1. one Agent + independent verifier;
2. two independent Tasks with disjoint participant identity, separately produced Artifacts, and one deterministic Join.

Both cells must bind the same owner evidence, consequence ceiling, Provider/model family where applicable, Runtime limits, verifier, and final acceptance law. Branches cannot communicate through hidden shared mutable state.

The first experiment should use ordinary existing Host Task and Runtime Artifact semantics before adding any new participant protocol.

## Measurements

At minimum measure:

- authoritative accepted outcome;
- independently discovered errors or hypotheses;
- Provider tokens and Runtime work;
- duplicate or conflicting Effects;
- responsibility ambiguity;
- Join completeness and deterministic replay;
- interruption/recovery behavior;
- operator or consequence-authority intervention.

## First falsifier

A single Agent plus independent verifier matches or exceeds two independent branches on accepted result, error discovery, cost, duplicate-Effect rate, responsibility clarity, and recovery; or ordinary Host Task/Artifact semantics express branch and Join without a new shared coordination primitive.

## Ownership hypothesis

```text
Computer
  experiment / comparison / admission or deletion

Host
  Goal / Task / participant responsibility / commitment / final Outcome

Harness
  each independent Agent Run and its cognition

Runtime
  Workspace / Job / Attempt / Artifact physical truth

Domain verifier
  authoritative semantic acceptance
```

The experiment does not presuppose a shared Multi-Agent message bus, organization object, agent society, scheduler, or graph runtime. If ordinary owner-native objects are sufficient, the correct result is to retain them and delete the abstraction proposal.

## Admission boundary

A new shared coordination primitive is admissible only if the minimum workload exposes a repeated responsibility that cannot be expressed cleanly by current Task, Artifact, verifier, and deterministic Join composition. Any candidate must state its owner, protected failure, measured benefit, recovery path, and deletion trigger.

## Deletion outcome

If falsified:

- keep independent-verifier and ordinary Task/Artifact patterns that earned value;
- do not build a generic Multi-Agent framework, scheduler, organization layer, Agent VM, shared memory bus, or permanent participant registry;
- retain exact negative evidence for later workloads.

## P4 live evidence

P4 froze nine pure-Python repair Goals (six development, three holdout), with hidden evaluator cases outside Agent-visible context. Each treatment had two semantic candidate slots and the same DeepSeek model, independent verifier, source gate, and deterministic Join. `single-reflect` used one participant across two calls, with visible-only feedback before the second candidate. `multi-independent` used two fresh participant identities with one call each and no communication. Neither branch could perform Effects.

The first campaign was invalidated rather than scored because the baseline runner violated the Provider history contract and a few Provider presentations failed. V2 changed only that presentation boundary. All 36 V2 candidate slots completed on their first Provider attempt. Development favored Multi **6/6 Goals versus 4/6**, while frozen holdout tied **2/3 versus 2/3**. Combined Goal acceptance was 8/9 versus 6/9, but candidate-level authoritative case coverage was actually 76/84 versus 78/84, showing higher diversity rather than uniform correctness. The holdout errors were complementary: Multi rescued one Goal that sequential reflection missed, and sequential reflection rescued another that Multi missed. Multi used about 88.6% of baseline Provider tokens, but the pre-registered rule required strict superiority on both splits, so generic Multi advantage was rejected.

Mechanically, current `GoalCoordinatorHost` was sufficient. Across 18 treatment Goals there were zero branch Effect intents, zero responsibility ambiguities, no recovery failures, and no rejected-verification advancement. All 14 accepted treatment Goals invalidated stale snapshots correctly. A separate deterministic smoke bound two digest-addressed candidate Artifacts to their respective Task revisions, reopened Host storage between result applications, and completed without any new coordination primitive.

Therefore the first falsifier is satisfied on this workload in the conservative direction: **do not build a generic Multi-Agent framework.** The useful retained pattern is optional independent branching behind explicit participant identity, Artifact provenance, independent Verification, and deterministic Join. What remains unproven is a cross-workload policy for when branching should be selected.
