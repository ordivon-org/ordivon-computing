# Ordivon Computer Agent-Native Lineage, 2026-07-24 to 2026-08-25

> **Historical lineage, not current architecture authority.** This page preserves how the Agent-native Computer problem changed under evidence. Current architecture is owned by `core/`, `research/computer-responsibility-map-v2.json`, current product repositories, and exact owner-native evidence. Historical proposals below are not reactivated by being recorded here.

## Why this history exists

The exact source history never disappeared. Git retained the original documents, experiments, deleted apparatus, protocol releases, and contraction closeouts. What became difficult to recover was the **causal intellectual lineage**:

```text
what problem was being asked
→ why a particular architecture looked necessary
→ which experiment or owner pressure weakened it
→ which responsibility survived the correction
→ where that surviving responsibility lives now
```

By 2026-08-25 a fresh reconstruction could recover the current responsibility map quickly but still miss that Ordivon Computer had originally asked a much stronger question: whether a computing stack designed around humans writing deterministic programs should be rebuilt when probabilistic Agents become primary planners, programmers, and operators. The later contraction was therefore easy to misread as if Ordivon had never seriously explored an Agent-native kernel/stack.

That is a lineage failure, not a Git-durability failure.

The current [`WORLD-MODEL-SEDIMENTATION-AUDIT-20260824.md`](WORLD-MODEL-SEDIMENTATION-AUDIT-20260824.md) already supplies the relevant failure taxonomy. This case combines:

1. **lineage-survival/migration debt** — historically integrated standing survives in Git but no longer has a compact current causal projection after contraction, branch movement, owner split, or rewrite;
2. **first-look/retrieval debt** — current Core and Research intentionally expose compact current responsibilities, so a relevant future Agent can enter the present architecture without naturally encountering the path that produced it;
3. **environmentalization debt** — “Git is the archaeology path” preserves bytes but does not itself make the recovered history part of ordinary future reasoning.

This page is the smallest repair: one bounded historical lineage plus first-look links. It does not create a history service, graph database, automatic recommender, or new semantic owner.

## Reading rule

Each phase below separates six things:

```text
Question
Historical proposal
Pressure / falsifier
Correction
What survived
What did not survive
```

A later correction does not make the earlier proposal foolish or false in every scope. In several cases the earlier prototype discovered distinctions that survived even though the proposed layer or ownership shape did not.

## Phase 0 — 2026-07-24: rebuild the computing stack?

**Local anchor:** `f752440` — `docs: establish agent-native computing research root`.

The initial research root was not “how should Ordivon wrap Linux?” It asked a substantially broader question:

> If probabilistic foundation models become primary planners, programmers, and system operators, which abstractions inherited from human-authored deterministic computing remain valid, which need new contracts, and which should be rebuilt?

The first stack walked from physical devices and compute primitives through memory/interconnect, ISA, host kernel/isolation, compilers, model runtime, Agent language/IR, execution kernel, world/tool interface, and organization/product layers. Horizontal concerns included identity, capability, state/memory, evidence/verification, and time/recovery.

### Historical proposal

Treat the whole computing stack as open to re-examination rather than assuming that the Human/program-centric arrangement is timeless.

### Constraint present from the beginning

The same root already carried a counterweight that later became decisive:

> Own irreducible semantics; reuse mature mechanisms.

So the initial question was radical, but it was not an instruction to rewrite every lower layer.

### What survived

- the legitimacy of re-auditing inherited abstractions under a different primary cognitive consumer;
- the distinction between “Agent uses an old mechanism” and “Agent pressure creates a genuinely unowned responsibility”;
- cross-layer attention to identity, authority, evidence, recovery, and consequence.

### What did not survive

- the assumption that the answer would naturally be a new end-to-end Agent-native stack;
- the expectation that every historically Human-facing layer needs an Agent-specific replacement.

## Phase 1 — 2026-07-26: Agent Semantic Core / Kernel

**Local anchors:** `e5d545e`, `4c817cb`, `7d6d0b9`, `aec6269`.

The first concrete answer was strong: materialize an **Agent Semantic Core** between probabilistic cognition and physical executors. The experiment contained explicit identity, authority, world-object, Effect, Dispatch, Observation, Artifact, Claim, Verification, and Fact roles, plus an Ordivon adapter and reference kernel.

### Why this looked necessary

A model can generate an action description without establishing:

- that the action is authorized;
- that a physical attempt occurred;
- that an acknowledgement proves the intended Effect;
- that an Artifact proves the domain result;
- that model confidence is evidence;
- that a lost response means failure rather than `UNKNOWN`.

The Semantic Core made several distinctions explicit:

```text
Effect != Dispatch
Observation != Fact
Artifact != Verification
Process exit != semantic completion
UNKNOWN != failed
```

and preserved the recovery law:

```text
lost response
→ reconcile the original effect/request identity
→ do not blindly redispatch
```

### Historical proposal

A central Agent-native semantic admission/kernel layer could own the stable objects required to mediate probabilistic intent and deterministic/world-changing execution.

### Pressure / falsifier

As the project compared those objects against operating systems, databases, durable workflows, version control, domain APIs, and real Ordivon owners, two problems became visible:

1. many mechanics were already correctly owned below the proposed kernel;
2. many meanings were not actually universal — Finance, Game, Security, Runtime, Host, and other owners had different completion, evidence, authority, and world semantics.

### Correction

The important result was not “Semantic Core failed.” The **responsibility distinctions** were valuable, while the **central-kernel ownership shape** was too strong.

### What survived

- stable Effect/request identity when recovery needs it;
- physical attempt separate from semantic intent;
- explicit uncertainty and reconciliation;
- Observation / Artifact / Claim / Verification / completion separation;
- authority outside model preference;
- exact Tool/contract binding where drift matters.

### What did not survive

- one universal semantic state owner;
- one central kernel that interprets all domain meaning;
- the assumption that every surviving distinction deserves a permanent shared object.

## Phase 2 — 2026-07-29: classical substrate + Agent-native overlay

**Local anchor:** `dfbee16` — `research: define classical substrate and agent-native overlay`.

The eight-part `studies/2026-classical-to-agent-native-computing/` study changed the problem representation.

The key observation was that classical computing is not distinguished by perfect determinism. Classical systems already contain races, partial failure, network uncertainty, crashes, nondeterministic scheduling, and external faults. Their structural advantage is that software normally **predeclares operational objects, legal transitions, and completion rules**.

Agent systems move part of program construction into runtime:

```text
human/domain purpose
→ selected Context
→ probabilistic interpretation
→ proposal
→ admission
→ commitment
→ execution
→ evidence
→ revision
```

### Historical proposal

Keep the classical deterministic substrate authoritative for its mature mechanics, and place an Agent-native semantic/work overlay above it for the responsibilities created by open probabilistic cognition.

A historical R0–R7 overlay separated purpose/consequence ownership, operator attention, open-work continuity, Context/memory compilation, cognition/coordination, authority/admission, Effect commitment/reconciliation, and evidence/verification.

### Pressure / falsifier

The overlay was already smaller than a replacement OS, but future-model and deletion tests asked whether its own subsystem categories were genuinely permanent. Stronger Providers might absorb planning, Tool loops, memory, subagents, code execution, or retrieval; mature lower systems might already satisfy some responsibilities; product owners might need only local adapters rather than shared layers.

### Correction

Replace subsystem-centric architecture with **responsibility-centric architecture**. A responsibility may be real without deserving an independent repository, service, protocol, or permanent layer.

### What survived

The current `ANC-STACK-001` question and the reusable responsibility-placement rule:

```text
ordinary reuse
!= Agent-amplified importance
!= genuinely new unowned responsibility
```

### What did not survive

- the overlay as a fixed stack of Agent-native subsystems;
- the assumption that Memory, World, Harness, organization, graph, or cognition runtime deserve permanent architecture seats by category alone.

## Phase 3 — 2026-08-07: future-model-robust responsibility band

**Local anchor:** `c239dff` — `record Computer responsibility reform acceptance`.

The next reform applied a stronger test: if models and Providers become materially more capable, which responsibilities still cannot safely disappear into cognition or an existing lower owner?

The result was a thin middle band rather than an Agent platform stack. Current Core later expresses that band through responsibilities such as:

- durable open-work identity and continuity;
- current Context/source/revision binding;
- consequence and authority admission;
- Effect uncertainty and reconciliation;
- evidence / verification / accepted completion separation;
- Tool contract identity and drift;
- owner-native observation with derived projection rather than shadow authority.

### Historical proposal

Preserve only responsibilities that remain valuable across stronger models, Provider replacement, process replacement, response loss, authority change, and external-world uncertainty.

### Pressure / falsifier

Even a thin responsibility list could become a protected architecture if its own historical existence granted legitimacy.

### Correction

The next step would not be another construction phase. It would attack Computer itself.

## Phase 4 — 2026-08-10: removal-first Existence Gauntlet and contraction

**Local anchors:** `32014ce`, `e1e19ef`, `b7c3946`, `36d6474`, `1216605`, `2df4313`, `bf1fcc4`, `bb4c56e`, `0d4ca4e`, `0ea8415`.

This was the pivotal anti-platform phase. Instead of asking what else Computer should build, the research asked which existing Computer features still deserved to exist.

The full Existence Gauntlet attacked 47 features with control-plane semantic mutants, protocol ablation, content-stack deletion, active-tree shadow contraction, global-method falsification, consumer checks, and exact `retain/narrow/localize/archive/delete/inconclusive` dispositions.

### Historical proposal

No existing abstraction, test suite, protocol, or research apparatus receives a presumption of survival from age, elegance, implementation effort, or documentation volume.

### Correction embodied in current Core

The default re-audit candidate becomes removal from the active path. Retention requires a current consumer, a concrete protected failure/capability, evidence that a narrower owner-local or mature mechanism is insufficient, recurring net benefit, and a reopen/deletion condition.

### Concrete consequences

- historical executable research apparatus left the active tree while exact Git history remained recoverable;
- several proposed shared layers were localized, archived, or deleted;
- the global research method machinery was replaced by a much smaller experiment-local contract;
- Protocol `0.3.0` remained immutable while the current unreleased `0.4.0.dev0` candidate removed the zero-current-consumer `ordivon_semantics` implementation;
- no consumer was silently upgraded merely because current source contracted.

### Why this matters to the earlier Semantic Kernel history

The deletion of current `ordivon_semantics` does **not** mean Ordivon never had a Semantic Kernel phase, nor that every Semantic Core distinction was rejected. It means the current active implementation no longer earned a shared semantic-state package.

### What survived

Current machine authority is [`computer-responsibility-map-v2.json`](computer-responsibility-map-v2.json), with a human projection in [`COMPUTER-RESPONSIBILITY-REVIEW.md`](COMPUTER-RESPONSIBILITY-REVIEW.md). Surviving responsibilities are placed at the lowest capable owner.

### What did not survive

- architecture nouns as permanent seats;
- zero-consumer semantic state implementation;
- historical experiment executability as a requirement for preserving learning;
- “Computer must always have a next architecture phase.”

## Phase 5 — 2026-08-14: Agent Situation without global Agent state

**Local anchor:** `5fc63a9` — `feat(observation): add owner-qualified agent situation projection`.

After Host, Harness, Runtime, and World developed strong owner-native projections, a fresh Agent still had to reconstruct a practical situation across owners:

- what work continuity exists;
- where the physical locus is;
- which facts are current;
- what action surface is installed;
- what is exactly admitted now;
- what physically occurred;
- what remains `UNKNOWN`;
- who owns recovery or semantic completion.

A natural “Agent OS” answer would be one global Agent state, presence registry, currentness table, or authority database.

### Experiment result

The P3 Situation experiment instead composed already-observed owner facts into a non-authoritative projection.

Across three workloads:

| Metric | Baseline | Situation treatment |
| --- | ---: | ---: |
| required owner reads | 8 | 8 |
| manual cross-owner joins | 10 | 0 |
| explicit unsafe implication opportunities | 10 | 0 |

The owner-read count intentionally did not improve. Currentness remains owner truth.

### Surviving law

> **Unified consumption does not require unified state, currentness, or authority.**

The current `ordivon_observation_core.situation` module therefore does not query owners, probe liveness, grant authority, select a locus, reconcile Effects, or infer semantic completion. It only performs bounded owner-qualified composition.

### What did not survive

- global Agent registry;
- universal Agent identity owner;
- global Presence/reachability table;
- single authority object spanning owners;
- Observation as a currentness service.

## Phase 6 — 2026-08-22: API correctness is not First Interface fitness

**Cross-owner historical anchors:**

- `task:ordivon-runtime-design-archaeology-and-mode-transition-audit-20260822` @ revision 3;
- `task:ordivon-host-tool-surface-mode-transition-audit-20260822` @ revision 3;
- `task:workstation-responsibility-position-rerepresentation-20260822` @ revision 8.

By this point another distinction became unavoidable:

```text
owner API / physical protocol
!= best first interface for a fresh Agent
```

### Runtime

The Runtime archaeology found that Workspace/Job/Attempt/Artifact had a real recovery/execution origin and remained deletion-positive for direct physical-protocol consumers such as Harness and Security. At the same time, live Job sampling and newer Finance/Workstation composition showed that raw Runtime vocabulary was increasingly being used as a cognition-level interaction waist even when domain owners had better semantic operations.

The retained conclusion was:

> `Runtime API != Runtime first interface`.

This did **not** authorize deleting low-level Runtime tools. It separated compatibility/owner protocol from Agent-facing ergonomics.

### Host

Fresh-Agent tests found that Host `task.list`/`READY` could be misread as current work/priority authority. The durable continuity core was healthy; the representation was wrong for the new operating mode.

The repair was deliberately small: clarify that `READY` means open Host continuity only and that `task.list` is continuity inventory, not portfolio/current-work/priority truth. No universal Task v2, WAIT/HOLD/BLOCKED lifecycle, priority engine, or new endpoint was earned. The live post-repair Fresh-Agent dogfood passed 9/9.

### Workstation

Workstation was re-represented as the **Execution-Node Substrate & Physical Realization/Binding Authority** rather than an independently exposed semantic control plane. Its public MCP was retired; the external Ordivon control surface remained Host + Runtime, while Workstation owner operations were consumed internally through Runtime/domain paths.

The stable ownership law became:

```text
Workstation physical availability
!= cross-locus serviceability
!= domain admission
```

### Cross-owner implication

The architecture was becoming less like a central Agent OS service graph and more like a set of owner-native semantic environments over shared execution machinery.

## Phase 7 — 2026-08-22 to 2026-08-24: First Interface and operation-relative affordance recompilation

**Host historical anchor:** `task:ordivon-first-interface-environmentalization-ppd-20260822` @ revision 29.

The problem moved again. The question was no longer mainly which semantic objects should exist. It became:

> What should an Agent actually see and be allowed to choose **now**, given current owner standing and the current operation?

### Finance positive control

Finance showed that an ordinary observe flow should not force the Agent to reconstruct an already mechanically resolvable active Goal or repository/runtime plumbing. A bounded owner operation could sink those coordinates while preserving Finance-owned meaning and authority.

### Atlas negative/positive control

Atlas showed the opposite boundary. The initial semantic research query is genuinely cognitive and must remain visible. But once a stable first-look candidate exists, repeated ambient re-query freedom becomes harmful; the next useful affordance becomes bounded candidate inspection.

Therefore:

```text
FirstInterface != fewer parameters
FirstInterface != zero-argument tools
FirstInterface = operation-relative affordance recompilation
```

or, in the retained wording:

> **grounded semantic freedom** — sink mechanically resolvable identity/environment/currentness plumbing, retain genuine semantic choice, and withdraw stale/unhelpful freedoms after owner standing changes.

### Mixed-catalog falsifier

A mixed surface exposing Finance, Atlas, Host, and raw Runtime simultaneously was tested with neutral routing. Fresh Agents chose the correct first action 12/12 without a centralized semantic router.

### What survived

A composition pattern:

```text
owner truth / current standing
→ owner- or application-local bounded projection
→ grounded current affordances
→ generic presentation / Tool carriers
→ Agent semantic selection
→ exact owner admission / Runtime realization
→ new owner/world evidence
→ recompile the next affordance set
```

### What did not survive

- universal FirstInterface service;
- global semantic router;
- CurrentWork ontology;
- Environment manager;
- global relation graph;
- the claim that every semantic Tool should be zero-argument.

This phase is important because it changes the meaning of “Agent-native computing.” A system can retain mature operating systems and owner APIs while still being non-Agent-native if the Agent must repeatedly reconstruct identity, currentness, ownership, or mechanical plumbing that the environment could expose correctly.

## Phase 8 — 2026-08-24 to 2026-08-25: from interface to representation environment

**Current cross-owner theory anchor:** [`WORLD-MODEL-SEDIMENTATION-AUDIT-20260824.md`](WORLD-MODEL-SEDIMENTATION-AUDIT-20260824.md).

**Open Host research anchor:** `task:ordivon-representation-environment-audit-20260825` @ revision 6 as observed during this repair.

The frontier widened from Tool ergonomics to the **observer/operation-relative cognition habitat** itself:

- first object;
- search geometry;
- source/currentness recovery;
- Context formation;
- Tool/action exposure;
- result interpretation;
- handoff/continuation;
- Human/Agent representation where the consumer requires it.

The Representation Environment audit has already supplied a useful methodological control. A theoretically rich Conversation-specific representation was not promoted merely because it seemed natural: after evaluator cleanup, generic Live handling already preserved the tested ambiguity in 3/3 runs, so extra discourse-state machinery had no deletion-essential marginal capability. The stable result was written back to the Media owner rather than left conversation-only.

That is itself part of the lineage:

> Agent-native environment work is not permission to create a universal representation layer. Representation must earn its carrier through consumer failure, owner placement, and bounded ablation just like every earlier Computer layer.

### Current frontier, not closed conclusion

The strongest current synthesis is no longer “build an Agent Semantic Kernel” or even “build an Agent-native overlay.” It is closer to:

```text
owner-native reality
+ thin durable responsibility boundaries
+ operation-relative representation / affordance environment
+ mature physical substrate
```

This is a **working synthesis**. Current owner repositories and Core remain authoritative; the open Representation Environment Task may still revise it.

## Why the history became easy to forget

### 1. Successful contraction removed the original shapes from the active path

The 2026-08-10 reform was intentionally deletion-positive. Historical executable apparatus and zero-consumer structures were removed from current source. This correctly prevented stale architecture from remaining ambient, but also made the original hypothesis space less visible.

The rule:

```text
Git preserves exact archaeology
```

was necessary but not sufficient for ordinary causal recovery.

### 2. Current Core is intentionally a compressed prior, not a history book

Core should not carry every historical derivation. It preserves compact surviving responsibilities. This makes current decisions cheaper but necessarily hides the sequence of rejected alternatives unless another history surface exists.

### 3. “Current truth” and “historical explanation” were correctly separated, but the second carrier was missing

`ANC-STACK-001`, `computer-responsibility-map-v2.json`, Protocol candidate state, and owner docs correctly answer current architectural questions. None of them was designed to explain why Semantic Core once looked right and why its responsibilities later decentralized.

### 4. Cross-owner evolution outgrew one repository

The later lineage is distributed across Computing Git plus Host-tracked Runtime, Host, Harness/First Interface, Workstation, Finance, Atlas, and Media work. A future Agent looking only at Computing local history can therefore recover the early contraction but miss the later environment shift.

### 5. First-look favored current actionability over ancestry

That is usually correct. But for a repeated foundational question — “why not build an Agent OS / Semantic Kernel?” — ancestry changes the decision. Without a lineage link, a fresh Agent can reopen an already deeply explored architecture branch from first principles.

### 6. History was preserved as bytes, not inhabited as a reusable relation

This is the same distinction now used elsewhere in Ordivon:

```text
Preserved history
!= discoverable history
!= selected history
!= environmentalized history
```

So “we forgot” is too weak. The more precise failure is:

> **The exact historical evidence survived, but the causal lineage was not present in the ordinary representation environment of the question that needed it.**

## What this history should prevent

This page should make the following future errors harder:

### Error A — treating the current thin architecture as if the larger question was never investigated

The current contraction is an evidence result, not an initial conservative preference.

### Error B — recreating a central Semantic Kernel because the original experiment is no longer visible

Before reopening that path, identify the new owner-native failure that defeats the later contraction.

### Error C — treating every historical semantic distinction as a current shared schema requirement

A distinction can survive as a responsibility while its old object/package disappears.

### Error D — treating “reuse Linux/Windows” as the whole answer

The later First Interface/Representation work shows that inherited physical mechanisms can remain correct while their consumer-facing representation remains badly shaped for an Agent.

### Error E — centralizing Situation/currentness/authority to reduce owner reads

The 2026-08-14 ablation specifically retained all owner reads while deleting manual joins and unsafe implications.

### Error F — equating fewer Tool parameters with Agent-native design

Finance and Atlas form a deliberate heterogeneous control: remove mechanically resolvable coordinates, retain genuine semantic coordinates, then recompile affordances as standing changes.

## Current standing after this repair

The current historical interpretation is:

> Ordivon Computer began by asking whether Agent-primary computing requires rebuilding the stack. It prototyped a Semantic Kernel, then discovered that many mechanics should remain classical and many meanings should remain owner-local. The architecture contracted first into a thin responsibility band, then survived a removal-first existence attack. Subsequent Situation and First Interface experiments showed that the remaining Agent-native problem is not one centralized state/kernel but the reliable composition and representation of owner-native reality into an operation-relative environment where a finite Agent sees current, grounded semantic freedom without inheriting unnecessary plumbing or false authority.

This is a historical synthesis, not a new Core axiom.

## Reopen rule

Reopen the historical interpretation when a materially new owner-native failure demonstrates one of the following:

- a centralized semantic/currentness/authority owner becomes deletion-essential across heterogeneous consumers;
- operation-relative owner-local composition cannot preserve required identity, recovery, or consequence semantics;
- mature OS/workflow/database substrate becomes the actual recurring blocker rather than its representation/binding;
- substantially stronger Agents eliminate a responsibility currently retained in the middle band;
- a lower-layer/kernel mechanism becomes the narrowest owner of a proven non-bypassable invariant.

Do not reopen merely because an old architecture name sounds newly fashionable.
