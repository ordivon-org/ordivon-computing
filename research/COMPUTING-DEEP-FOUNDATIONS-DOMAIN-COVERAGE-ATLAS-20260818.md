# Ordivon Computing — Fresh Whole-Domain Coverage Atlas

## 0. Why this search exists

Ordivon Computing contains unusually deep local work on Agent-era responsibility, adaptation, evidence, authority, recovery, causal explanation and owner placement. That depth can create a false impression that the referent **Computing** itself has already been reconstructed from first principles.

This atlas tests the opposite hypothesis:

```text
Deep Agent-system research
!= Whole-Computing foundation coverage.
```

No `CDF0` is admitted here.

---

# 1. Current Computing Core is not a theory of computation

The current Core is primarily a compact architecture/research prior for Ordivon Agent systems.

Its surviving concerns include:

```text
open-work identity
Context binding
consequence/authority
Effect uncertainty/reconciliation
evidence/verification/completion
Tool contract drift
owner-native observation
cross-owner contract admission
bounded self-reform discipline
```

These are valuable Agent-era system responsibilities.

But they do not answer foundational Computing questions such as:

```text
what counts as computation?
what is computable?
what resources make one computation harder than another?
what changes when computation is interactive rather than closed-input/closed-output?
what correctness means for approximate/stochastic/ongoing systems?
what semantic relation connects program/representation to behavior?
what impossibility follows from concurrency/distribution/failure assumptions?
what physical assumptions matter to computation?
```

Therefore:

```text
Current Computing Core
!= Computing Foundations closure.
```

# 4. Major underexplored continents


This is foundationally central and currently underrepresented.

Status: `MAJOR UNDEREXPLORED CONTINENT`.

## U2 — Complexity and plural resource theory

Current coverage is especially thin.

Classical complexity asks not only **whether** a result is computable but at what resource cost.

Potential resources include:

```text
time
space
communication
I/O/data movement
parallel depth
random bits
energy
precision
samples
queries
synchronization
rounds
bandwidth
human/Agent attention
external-effect budget
```

The central open question is whether Computing needs a generic resource-relative notion or several irreducible cost regimes.

Status: `VERY HIGH INFORMATION GAIN`.

## U3 — Interactive / reactive / ongoing computation

The repository has strong Runtime/Agent interactions but almost no explicit theory of **interactive computation** itself.

Pressure:

```text
closed function evaluation:
input -> compute -> output

vs

interactive system:
input/output/world coupling continues while the computation is alive.
```

Persistent Turing-machine and transition-system work is a direct pre-Agent warning that closed function semantics may be too narrow for databases, services and Agents.

Status: `VERY HIGH INFORMATION GAIN`.

## U4 — Algorithms, lower bounds and data structures

## U11 — Information / coding / algorithmic information

## U12 — Real-time / embedded / cyber-physical computation

Runtime research covers execution timing/lifecycle, but whole Computing has not reconstructed computation where deadlines and physical coupling are part of correctness.

Questions:

```text

```

Status: `UNDEREXPLORED / Runtime-World boundary`.

## U13 — Reversible / thermodynamic computation

Bennett's reversible-computation construction and later thermodynamic work show that logical transformation structure affects physical dissipation constraints.

This pressures the assumption that energy is merely hardware implementation detail.

Status: `NEAR-ABSENT / HIGH FALSIFICATION VALUE`.

## U14 — Analog / continuous computation

Near-zero repository coverage.

Potential pressures:

```text

computable analysis
```

Status: `NEAR-ABSENT / HIGH FALSIFICATION VALUE`.

## U15 — Biological / molecular / neuromorphic computation

No meaningful current coverage found.

These regimes test whether:

```text

```

Status: `ABSENT / HIGH ANTI-BIAS VALUE`.

## U16 — Quantum computation

No meaningful current coverage found.

Quantum computation preserves computability boundaries in familiar ways while changing efficient complexity classes, information structure, measurement and reversibility assumptions.

Status: `ABSENT / HIGH ANTI-BIAS VALUE`.

## Network owns


## World owns

```text

```

Physical computation research must distinguish computation-relative description from World truth.

## Human owns


Computing may study adversarial algorithms/cryptographic cost only where a generic computational question survives Security ownership.

# 6. Rival minimal models of the Computing referent

Do not select one yet.

## M1 — Function evaluation

```text
Computation = mapping input to output.
```

Strength: classical algorithms/functions.
Weakness: interaction, persistence, effects, ongoing systems.

## M2 — Controlled state transition

```text
Computation = rule-governed transformation of represented state.
```

Strength: machines, programs, memory, dynamical models.
Weakness: risks swallowing arbitrary physics unless representation/control criteria are added.

## M3 — Information transformation

```text
Computation = transformation/transmission of information-bearing distinctions.
```

Strength: coding, algorithms, physical systems.
Weakness: risks pancomputationalism; information itself needs grounding.

## M4 — Effective procedure

```text
Computation = realizable effective procedure under a declared model.
```

Strength: computability/algorithms.
Weakness: interactive/learning/physical systems challenge a static-procedure reading.

## M5 — Resource-bounded process

```text
Computation = state/information transformation whose possibility and usefulness are defined relative to resource constraints.
```

Strength: complexity, hardware, distributed, approximate regimes.
Weakness: resource plurality may prevent one canonical metric.

## M6 — Interactive process

```text
Computation = ongoing process coupled to an environment through streams/actions/observations.
```

Strength: services, databases, Agents, reactive systems.
Weakness: may overfit ongoing systems and underdescribe closed algorithms.

## M7 — Physical realization of abstract transformation

```text
Computation = physically realized transformation interpreted under an abstract computational model.
```

Strength: analog, reversible, quantum, hardware grounding.
Weakness: representation/interpretation criteria risk observer dependence.

Current verdict:

```text
NO MODEL SELECTED.
```

The first Computing Foundation candidate, if any, should emerge only after destructive comparison across these rival models.

# 9. External theory pressure already sufficient to reject a narrow digital-function prior

Three examples are enough to show why the search must stay broad:

## Interactive computation

Persistent Turing-machine work models sequential interactive systems as ongoing input/output streams with persistent internal state and relates them to interactive transition systems.

Pressure:

```text
closed input -> output function
may be insufficient for ongoing computation.
```

## Distributed impossibility

FLP shows that deterministic consensus termination is impossible in a fully asynchronous model with even one faulty process.

Pressure:

```text
algorithm text alone
!= computational possibility;
environment/failure model matters.
```

## Reversible computation

Bennett showed ordinary irreversible computation can be simulated by a logically reversible machine while retaining general computational ability.

Pressure:

```text
same abstract computability
can coexist with materially different information-erasure/physical-cost structure.
```

These examples do not select a foundation. They demonstrate that a Computing foundation biased toward current Ordivon software mechanisms would be too narrow.
