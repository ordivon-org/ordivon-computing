# SCD + Computational Possibility Engineering Consumption Audit — 2026-08-18

Status: **CLOSED — OWNER-SPECIFIC ENGINEERING BOUNDARIES MATERIALIZED; NO NEW RUNTIME SERVICE OR CORE EXPANSION ADMITTED**.

This audit distinguishes two semantic owners that share the `ordivon-computing` physical repository from Computer's own cross-project synthesis/product responsibilities.

## SCD disposition

Current Computing/product surfaces already use schemas, Tool contracts, versioned protocol artifacts, Binding, normalization, representation and conformance. They generally make narrow structural/operational claims rather than claiming universal semantic equivalence.

The missing piece was an explicit owner-specific engineering rule for when those surfaces cross into SCD truth.

New canonical boundary: [`../core/semantics-of-computational-descriptions/ENGINEERING-CONSUMPTION-INDEX.md`](../core/semantics-of-computational-descriptions/ENGINEERING-CONSUMPTION-INDEX.md).

Key engineering law:

```text
schema / digest / parser / version compatibility
!=
semantic equivalence / refinement / preservation
```

No current evidence justifies an SCD service, registry, universal IR, or new shared protocol object.

## Computational Possibility disposition

CP already exposes a thin [`../core/computational-possibility/ENGINEERING-CONSUMPTION-INDEX.md`](../core/computational-possibility/ENGINEERING-CONSUMPTION-INDEX.md) and Applicability/Theorem-Transport bridge.

The audit keeps that surface thin. Engineering may consume CP when it makes a **regime-relative possibility/impossibility, reduction, simulation, witness, resource/complexity or applicability claim**.

Key law:

```text
implementation succeeded once
!= theorem of possibility for a broader regime

implementation failed
!= theorem of impossibility

benchmark / cost observation
!= complexity lower or upper bound without the required regime/obligation semantics
```

A CP claim must name the relevant computational obligation/problem role, regime/information interface, witness/certificate or reduction/simulation profile when load-bearing, and theorem scope.

The historical computational-applicability/theorem-transport apparatus remains derived instrumentation, not a production gate, service, theorem registry or automatic currentness mechanism. No engineering action in this audit depends on resurrecting or preserving any particular experiment implementation.

## Current project consequences

### `ordivon-protocol`

Retain exact versioned contract/conformance authority. Do not reinterpret structural compatibility as SCD semantic preservation. Promote a semantics-sensitive compatibility rule only after real cross-repository consumers require it.

### Tool / Binding surfaces

Retain exact contract/revision/digest Binding for execution/recovery. Where a decision specifically claims that a changed Tool is a semantic substitute or refinement, source-fence that claim to an explicit SCD relation and test scope.

### Computing Core / Knowledge

Computer may explain SCD/CP distinctions, but does not become their semantic owner. No Core primitive is added by this audit.

### Runtime / Harness

Runtime keeps actual realization, Attempt/lifecycle/evidence and support/reconciliation truth. Harness keeps Run/context/invocation/tool-control truth. SCD/CP may constrain abstract claims imported by these owners; they do not absorb their execution/orchestration state.

## Non-admissions

This audit does not admit:

- new SCDF or CP Foundation;
- SemanticCompatibilityService;
- TheoremTransportService;
- global theorem/applicability registry;
- automatic semantic migration gate for every schema change;
- automatic impossibility inference from failed execution;
- automatic complexity inference from benchmark data;
- movement of SCD/CP truth into Computer Core.

## Reopen

Reopen only on a concrete engineering failure such as:

1. a real protocol/tool migration passes structural compatibility but violates required semantic preservation;
2. two consumers independently need the same explicit equivalence/refinement/property-preservation contract;
3. a product decision makes a possibility/impossibility/applicability claim whose correctness depends on unrepresented regime/witness/reduction semantics;
4. repeated engineering work reconstructs the same theorem-transport or semantic-compatibility proof burden and owner-local composition is insufficient.
