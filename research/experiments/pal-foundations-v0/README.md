# PAL Foundations v0

Status: **Computing-local foundational research. Not an Ordivon architecture or reform program.**

## Mission

Determine which mechanisms make an adaptive change become reusable, transferable, self-correcting and eventually capable of improving future improvement. Treat Persistent Adaptive Loop (PAL) as a family of competing hypotheses. Other Ordivon owners are read-only evidence sources / experimental worlds until a later Computing result earns a bounded consumption proposal.

## Non-authority boundary

This research does **not** authorize changes to Runtime, Host, Harness, World, Workstation, Finance, Security, Game, Web, Studio or Human. It does not create PALController, WML v3, a universal loop schema, an improvement score, a shared registry, or a new repository.

## Starting evidence

The first empirical block uses two unusually strong existing bodies of evidence:

1. the historical Agent-first reform lineage in Ordivon Computing, including broad early architecture, semantic-core-v0, later responsibility contraction, Agent-first research method, infrastructure-promotion rule, crosscut A0, and ACS owner consumption;
2. PAL R1 P1–P5, which already falsified `Persistent Change => Recursive Improvement Evidence` in four materially different ways and retained one scoped transfer success.

These are not treated as laws. They are cases from which competing explanations must make different predictions.

## F0 hypothesis families

The machine-readable candidates are frozen in `hypothesis-families-v0.json`.

The initial families deliberately overlap:

- **H-PERSIST** — persistence/availability itself is the main driver of later improvement;
- **H-DEPTH** — deeper change classes (method/meta-selection) compound more reliably than state/capability/policy changes;
- **H-RESP** — future-model-robust responsibility placement and structural-advantage externalization drive durable transfer;
- **H-CREDIT** — local observability, evaluator alignment and short causal credit paths dominate transfer;
- **H-VARIATION** — candidate diversity is the binding constraint; selection cannot recover from a narrow hypothesis set;
- **H-REGULATION** — negative feedback, rollback, deletion and anti-Goodhart pressure are necessary for beneficial compounding rather than merely faster self-reinforcement.

No family is an invariant. F1–F4 exist to split them.

## First empirical block

### F1 — Agent-first historical prospective replay

Use only evidence available before each historical disposition to predict whether a candidate should be retained/shared, localized, deferred, or contracted. Compare naive persistence/current-convenience/architecture-symmetry baselines against the responsibility-placement model that later became Agent-first.

Question: **did the successful reform work because its selection rule was better, or because the surviving candidates were obvious in hindsight?**

### F2 — Change-depth predictive test

Test whether a simple hierarchy such as `state < capability < policy < knowledge < method < meta-selection` predicts later independent consumption. Compare it with a mechanism model using future-model robustness, owner clarity, measurable external outcome, causal distance and recurring maintenance cost.

Question: **does recursive depth itself predict compounding, or only mechanism/fit?**

### F3 — Transfer mechanism court

Compare P3 Game failure, P4 Security partial transfer, P5 Web success, Agent-first method/promotion-rule transfer and selected ACS controls. Competing explanations include abstraction level, domain similarity, determinism, local credit assignment, observability and action specificity.

Question: **why does one compressed prior become useful production capital while another becomes behavior without outcome?**

### F4 — Variation experiment

Only after F1–F3 expose a discriminating question, freeze a Provider experiment comparing single-candidate search with multiple independent variants under matched budget and an external oracle. F4 is intentionally not pre-solved here.

## Promotion rule

A PAL conclusion may move from this experiment directory into reusable Computing Knowledge only after it survives at least two materially different cases or one prospective held-out experiment plus a falsifier. Core eligibility is stricter: future-model robustness, repeated owner pressure and a deletion test are required. No owner engineering change follows automatically from Knowledge/Core promotion.

## Failure is a first-class result

A result that shows no stable PAL-specific mechanism is valid. A finding that existing Agent-first research discipline is already sufficient is valid. A finding that PAL should remain only a descriptive lens is valid.
