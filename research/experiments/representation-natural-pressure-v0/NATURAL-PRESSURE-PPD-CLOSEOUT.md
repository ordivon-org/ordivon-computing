# Representation Natural-Pressure Mode — Full PPD Closeout v0


> **Apparatus archive:** deterministic probe sources from this closed method audit are preserved as `*.py.txt` historical artifacts rather than active research executables. The exact original→archive path and SHA-256 mapping is retained in `../representation-natural-n1-v0/closed-representation-apparatus-archive.json`.

Status: **research-method closeout candidate / NO NEW TRIGGER LAYER**, 2026-08-25.

This closes the methodological question opened after Representation theory saturation:

> How can Ordivon notice and prospectively study naturally arising Representation pressure without either missing it or installing a global Representation monitor/recommender/causal-diagnosis plane?

The current answer is **composition of existing research mechanisms**, not a new subsystem.

## 1. Problem reformulation

The first formulation was too implementation-shaped:

`Need a Representation Natural Trigger Protocol`.

After internal/external subtraction, the real problem is:

> For one dormant research question with a frozen reopen/falsifier condition, when does ordinary owner/research evidence create enough pre-answer pressure to justify a local prospective experiment, what is the scientific time-zero, and what evidence class remains if urgent owner action happens first?

This is question-relative research admission, not continuous Representation monitoring.

## 2. Pressure

Natural-pressure mode must simultaneously handle:

- prospective vs retrospective contamination;
- owner-local work that should not inherit Computing semantic agenda;
- urgent mitigation/repair that must not be delayed for research purity;
- rare/heterogeneous events with no defensible frequency denominator;
- negative-control/no-op events;
- natural events that are real but irrelevant to the dormant question;
- future Agent/session replacement;
- temptation to treat every incident as support for a favorite open theory;
- temptation to keep theory branches alive by manufacturing synthetic positives.

## 3. Mature external subtraction

No generic methodological novelty is established.

Nearby mature methods already provide the needed ingredients:

- event-contingent/experience sampling: define qualifying events before observing them and retain missed/compliance limits;
- preregistration / Registered Reports: freeze hypotheses, methods, analysis/decision contingencies before answer-revealing observation while preserving exploratory work as a distinct class;
- target-trial thinking: align eligibility, contrast and time-zero; do not define eligibility using post-treatment/post-answer information;
- case-crossover/self-matched designs: useful only when transient exposure/acute outcome assumptions fit;
- sequential/anytime-valid methods: only when a coherent repeated stochastic stream exists;
- reliability/no-failure inference: zero events imply little without an exposure/failure model;
- Critical Incident Technique: systematically defined significant incidents can be collected prospectively or retrospectively for learning;
- SRE postmortems: owner mitigation/recovery and retrospective system learning remain valuable even when prospective causal identification is unavailable.

Therefore Ordivon should specialize these methods through existing owner/Research boundaries rather than create a Representation methodology service.

## 4. Internal subtraction — existing Ordivon already has the needed substrate

### 4.1 Question-local dormant reopen semantics

`research/portfolio.json` is canonical for Computing-local research status and requires every live question to carry `nextFalsifier` and `nextAction`.

`ANC-REPRESENTATION-001` already says:

- wait for a materially different natural Computing research-audit workload;
- do not build a service or run another synthetic treatment;
- freeze source revisions/oracle/admission before model runs;
- compare exact full source against the smallest source-bound target/claim + evidence + challenge + boundary projection;
- close/delete the candidate if value does not reproduce.

This is already a dormant prospective trigger.

### 4.2 Generic bounded experiment freeze

`experiment-contract-v1.json` already freezes:

- question/hypothesis;
- evidence selection;
- strong baseline;
- candidate/no-change;
- independent oracle;
- development/holdout split;
- invalidity;
- authority boundary;
- budget;
- stop/deletion/rollback rules.

No Representation-specific preregistration contract is required.

### 4.3 Prospective natural field studies already exist

PAL F14/F17 demonstrate post-t0 natural owner/external event admission without manufacturing events.

They already support:

- frozen t0;
- event admission criteria;
- negative controls/NO_OP;
- stop/window rules;
- downstream scientific oracle;
- explicit insufficient-evidence closeout;
- no automatic global scheduler/score/owner registry.

### 4.4 Automatic pressure discovery already failed its admission gate

C6 owner-pressure discovery did not graduate either selective or full-evidence selection and explicitly did not earn a selector service/daemon/registry.

This is direct negative evidence against a global Representation trigger selector.

### 4.5 Support-bound revalidation already exists

F18 shows one natural owner shift where retained prior clauses should be retained, strengthened or narrowed according to changed support conditions rather than wall-clock age/revision alone.

Thus dormant Representation standing can be revalidated when a real support condition changes; no TTL or automatic expiry is needed.

## 5. Retrospective eligibility audit

`eligibility_audit.py` tested seven historical/control cases plus hypothetical positive boundaries.

Historical cases were correctly contained as:

- retrospective/contaminated;
- owner-local regression;
- targeted SCD research;
- synthetic method evidence;
- natural event with no shared Representation decision lever;
- natural non-Representation capability demand;
- natural support-shift not itself a Representation pressure.

No historical case was retroactively promoted into prospective Representation evidence.

The hypothetical N1/N2/N3 boundary controls were admitted only when their defining conditions were explicitly present.

Standing: **specificity demonstrated on selected controls; future sensitivity unproven**.

## 6. Representation-specific trigger taxonomy deletion

`generic_composition_ablation.py` removed N1/N2/N3/G/R/A-specific global trigger fields from the decision path.

The selected audit/control decisions were reproduced using only:

1. natural vs targeted/synthetic evidence class;
2. whether answer-revealing inspection occurred before freeze;
3. owner-local vs shared decision lever;
4. current question's own `nextFalsifier/reopen condition`.

Therefore:

`RepresentationTriggerTaxonomy is not deletion-essential on the audited cases`.

A question-local nextFalsifier carries the domain-specific semantics; generic Research carries evidence class and prospective freeze.

## 7. Scientific time-zero

`time_zero_probe.py` established the following bounded method law:

`EventOnset != ScientificTimeZero`.

Scientific time-zero is the **first moment** at which the predeclared eligibility/contrast can be constituted from pre-answer evidence.

Consequences:

- safe/read-only triage may precede t0 if it does not reveal the answer;
- t0 cannot be backdated after implementation/history/root-cause inspection;
- urgent owner repair before freeze makes the case retrospective/postmortem for this causal question;
- research must never delay owner mitigation merely to preserve prospective purity.

## 8. No-trigger periods

`no_trigger_evidence_probe.py` establishes:

`NoTriggerObserved != TriggerAbsent`.

### Dormant mode

A `nextFalsifier` sitting in the portfolio has no enumerated exposure denominator. Thirty days with no noticed trigger has no frequency interpretation.

### Bounded field window

A field study may report `0/N inspected events`, but this remains descriptive unless its event sampling/stochastic model justifies a rate/probability claim.

### Model-based event stream

Only when exposure and stochastic assumptions are justified may zero-event statistics support formal bounds.

Therefore sparse/no-event periods normally support `insufficient evidence / remain dormant`, not scientific absence.

## 9. Prospective and postmortem are complementary channels

`two_channel_incident_probe.py` separates:

1. **prospective causal channel** — eligibility/contrast frozen before answer-revealing action;
2. **incident/postmortem channel** — timeline/direct observations/contributing causes/recovery/actions retained after significant owner incident.

A case can contribute to both.

If urgent repair happens first, prospective claim standing is lost but postmortem learning remains valid.

A retrospective postmortem may create/narrow a future `nextFalsifier`; it may not backdate a confirmatory contrast.

Thus:

`MissedProspectiveFreeze != ScientificallyUselessIncident`.

## 10. First-interface / continuity audit

Three surfaces must be distinguished:

`Stored != RecoverableOnResume != NaturallyEncounteredDuringOrdinaryWork`.

### Task-local recovery — PASS

Host `task.resume` for this COJC task returns exact current objective/frontier/established/unresolved/constraints/nextActions under a revision fence. The dormant/reopen methodology is recoverable across Agent/session replacement.

### Computing Research first look — PASS

`research/README.md` is a canonical `type:start`, `audience: agent`, `readiness: READY` entry. It explicitly sends the reader to `portfolio.json` / generated `PORTFOLIO.md` for current research status and Ready Frontier.

`PORTFOLIO.md` visibly contains `ANC-REPRESENTATION-001` with its exact natural-workload nextAction and nextFalsifier.

Therefore a fresh Agent that enters Computing Research can recover the dormant condition without repository archaeology.

### Ordinary owner work — INTENTIONALLY NOT INJECTED

Ordinary Harness/Finance/etc. owner-local work does not automatically receive Computing dormant questions.

`first_interface_deletion_probe.py` shows a global Representation question-card gains discovery only by injecting Computing semantic research agenda into ordinary owner-local work. This conflicts with ACS9's rejection of an owner-independent semantic `nextActions` recommender and with C6/F17 pressure-selection evidence.

A scoped card **after** the question is already selected may be a convenience rendering, but it is not deletion-essential to trigger discovery in the audited contexts.

Conclusion:

`No global trigger first-interface repair is earned`.

## 11. Final three-mode architecture — conceptual, not a state machine

### Mode A — Dormant question-local reopen (default)

Use when the residual is rare and there is no justified sampling denominator.

- keep canonical `nextFalsifier` / `nextAction`;
- no active monitor;
- ordinary Research/COJC consumption evaluates it when relevant evidence naturally enters scope;
- no-event time has no frequency interpretation.

### Mode B — Bounded prospective field study

Use only when trigger selection/sensitivity/specificity itself is worth measuring.

- freeze event admission/sampling/t0/contrast/oracle/stop/window;
- admit ordinary future owner/external events;
- retain NO_OP/negative controls;
- do not manufacture positives;
- close insufficient evidence if the window does not expose discriminating pressure.

F14/F17 are current exemplars, not universal templates.

### Mode C — Incident/postmortem learning

Use when consequence/urgency outruns prospective freeze.

- owner repair/mitigation first;
- retain direct timeline/evidence/recovery/contributing causes;
- mark causal interpretation retrospective/exploratory;
- use the incident to challenge or form a future nextFalsifier;
- never relabel it as predeclared causal evidence.

## 13. Rejected architecture

Do not build:

- Representation trigger daemon;
- global owner-event monitor for dormant Computing questions;
- Representation-specific trigger registry/taxonomy;
- owner-independent semantic next-action/research recommender;
- automatic G/R/A failure classifier;
- automatic promotion from owner event to COJC pressure;
- global event-frequency model over heterogeneous owner changes;
- trigger TTL based on time/revision;
- a new first-interface protocol solely for dormant Representation questions.

## 14. Remaining uncertainty

1. Dormant mode's **sensitivity** is unknown: because it has no systematic exposure denominator, one cannot estimate how many qualifying events are missed.
2. A bounded field study should be opened only if that sensitivity/opportunity-cost question itself becomes decision-relevant; otherwise monitoring cost can exceed evidence value.
3. New future consumer pressure may earn a compact question-card projection, but only after a real Agent repeatedly pays avoidable recovery cost relative to `README -> portfolio -> question` or Host resume.
4. N1/N2/N3/O4/O5 scientific residuals remain exactly as before; this method work changes how they are admitted, not their truth.
