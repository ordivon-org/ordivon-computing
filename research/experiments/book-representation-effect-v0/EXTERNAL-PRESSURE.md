# External solution-domain pressure

These sources constrain interpretation; they are not Ordivon owner truth and do not replace current Human/Media/Computing evidence.

## Long-context use is not uniform

- Liu et al. (2023), **Lost in the Middle: How Language Models Use Long Contexts**, arXiv:2307.03172. The paper demonstrates strong position sensitivity in long-context retrieval/QA and motivates separating nominal context length from reliable information use.
- Hsieh et al. (2024), **Found in the Middle: Calibrating Positional Attention Bias Improves Long Context Utilization**, arXiv:2406.16008. It connects long-context failure to intrinsic attention bias and shows that representation/position can alter usable context.

Consequence for this programme: Agent “delay” is not represented as wall-clock waiting. We separately test source removal, bounded persistent traces and unrelated intervening context.

## Human immediate performance, retention and transfer are distinct

- McDermott (2021), **Practicing Retrieval Facilitates Learning**, *Annual Review of Psychology*, PubMed PMID 33006925.
- Pan & Rickard (2018), **Transfer of test-enhanced learning: Meta-analytic review and synthesis**, *Psychological Bulletin*, PubMed PMID 29733621.
- Cognitive-load / element-interactivity work emphasizes that experienced task complexity depends jointly on information structure and prior knowledge; explicit support can therefore have different value for different consumers.

Consequence: a future Human representation claim must separately measure immediate comprehension, delayed unaided recovery and transfer, and must preserve prior-knowledge/task-complexity moderators. Current Human owner policy requires transport analysis and natural dogfood before residual direct comparison.

## DeepSeek model identity is not a scalar capability proof

Current DeepSeek API documentation lists `deepseek-v4-flash` and `deepseek-v4-pro` as separate current Chat models, both with large context support. DeepSeek's own V4-Flash release material describes Flash as approaching Pro and performing on par on some simple Agent tasks. Therefore this programme reports **provider-variant sensitivity**, not a universal `Pro > Flash` capability law.
