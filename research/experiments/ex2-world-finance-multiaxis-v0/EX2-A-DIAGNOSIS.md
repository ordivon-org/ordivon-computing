# EX2-A diagnosis — fixed axes are the wrong explanatory object

The preregistered five-axis matrix was rejected. Both treatments scored exactly 352/720 axis-set matches (48.89%). Whole-case exactness was 3/144 for the compact control and 11/144 for the explicit-five-axis treatment. Critical external-effect ownership remained below the safety target (85% / 80%).

The failure is structural rather than a prose preference.

## 1. The benchmark asked latent questions that the scenario did not ask

A fixed five-column record requires `semanticChoice`, `durableStructuralState`, `physicalTruth`, `externalEffectTruth`, and `sharingDisposition` for every case. Many cases do not have a live semantic choice or external consequence question. Models repeatedly answered `NONE` in mechanical Runtime lineage, reconciliation, classical scheduling, and rejected-abstraction cases while the oracle injected a broader upstream Agent/domain choice.

An explanation should be **question-relative**: preserve the relations needed to answer the present uncertainty, not complete a universal row.

## 2. State semantics and persistence carrier are different relations

World demonstrates the strongest counterexample. World owns the typed semantics of provider/Resource/Message/Entity journals, while the durable bytes are intentionally carried in Host CAS/extension continuity. Writing `durableStructuralState=[WORLD,HOST]` hides the distinction.

Retain separate claims:

- `OWNS_STATE_SEMANTICS(World, WorldTrajectoryState)`
- `PERSISTS_VIA(WorldTrajectoryState, HostExtensionCAS)`

Likewise a Finance research policy can be Finance-owned while Runtime physically seals exact input bytes.

## 3. “Physical truth” collapses unlike evidence roles

The rejected axis mixed at least four relations:

- native occurrence/state, e.g. OKX order/fill or Security materialization;
- local process/byte proof, e.g. Runtime Job/Artifact evidence;
- normalization/derivation, e.g. Finance reconciliation assessment or Capital Ledger materialization;
- cross-object integrity proof, e.g. World Browser bundle verification.

These are not co-owners of one truth. They are different transformations and proof boundaries.

## 4. Sharing disposition contains three independent decisions

`FINANCE_LOCAL`, `DELEGATE_CLASSICAL`, and `NO_SHARED_MECHANISM` can all be true for one optimizer case, but for different reasons:

- semantic home: Finance;
- mechanical implementation: mature numerical library;
- promotion status: no new shared Ordivon engine.

Similarly provider-native truth may coexist with a narrow shared World correlation contract.

Retain separate relations:

- `SEMANTIC_HOME`
- `DELEGATES_MECHANICS_TO`
- `PROMOTION_STATUS`

## 5. Time is source-bound relation, not a truth-owner set

Provider completion T1, World first availability T2, and Host admission T3 are separate coordinates with different meanings. Model them as `TIME_COORDINATE(source, meaning)` rather than asking all three to inhabit one `physicalTruth` field.

## EX2-B revision

The next representation is a typed responsibility relation model. It is not a graph service or product ontology. Relations are emitted only when relevant to the question being answered.

Candidate relation vocabulary:

- `DECIDES_SEMANTICS(actor, subject)`
- `OWNS_STATE_SEMANTICS(owner, state)`
- `PERSISTS_VIA(state, carrier)`
- `PROVES_NATIVE_FACT(owner, fact)`
- `PROVES_LOCAL_EXECUTION(owner, operation)`
- `MAPS_OR_DERIVES(mapper, source_fact, derived_fact)`
- `RECONCILES_IDENTITY(owner, effect_identity)`
- `ADMITS_CONSEQUENCE(authority, consequence)`
- `VERIFIES_ACCEPTANCE(verifier, evidence, objective)`
- `TIME_COORDINATE(owner, coordinate_meaning)`
- `SEMANTIC_HOME(responsibility, scope)`
- `DELEGATES_MECHANICS_TO(responsibility, substrate)`
- `PROMOTION_STATUS(responsibility, status)`
- `DOES_NOT_IMPLY(fact_a, fact_b)`

The relation vocabulary is experiment-local. EX2-B must test whether it reduces observed category errors on new cases before any promotion.
