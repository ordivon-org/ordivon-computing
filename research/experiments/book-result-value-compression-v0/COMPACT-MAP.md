# Result / Achievement / Value Compact Map — treatment-only experimental representation

Truth role: non-authoritative experimental compression of already-durable Atlas synthesis. This file is not Book content and does not create a Result owner, score, database, pipeline, or policy.

The result space is **orthogonal, not a maturity ladder**.

## Distinctions

- `Completed / Done` — an execution or continuity lifecycle ended.
- `Output` — an artifact, trace, code change, model output, document, or other produced object exists. Completion does not prove the output is correct.
- `Outcome` — an observed consequence occurred; it may be desired, adverse, mixed, or null.
- `Standing` — current evidence supports a claim under a declared scope/source/currentness boundary.
- `Progress` — movement toward a declared target without requiring threshold closure.
- `ObjectiveAchievement` — a declared objective, decision predicate, or uncertainty predicate is satisfied or materially closed.
- `DiscoveryAchievement` — an unplanned but independently standing-supported consequential gain occurs even if the original objective was not achieved.
- `Improvement` — a pairwise, scope-relative comparison. It needs a declared comparison scope including target/decision family, Reality/evidence bridge, constraints/resource envelope, horizon, protected consequences, and relevant recovery/future-option assumptions. A local metric gain alone is not sufficient.
- `Optimality` — stronger than improvement; it is relative to a justified feasible/search envelope and an explicit optimality notion. Local optimality is not global system improvement and there is no automatic open-world optimum.
- `ProspectiveValue` — a justified relation to possible future consequences/options under a declared future family. It is not proof of later use or benefit.
- `Consumption` — actual downstream use by a named consumer/use contract. A reference, citation, compatible practice, or mere availability does not by itself prove causal consumption.
- `RealizedBenefit` — an observed beneficial downstream consequence for a beneficiary with adequate attribution standing, scope/horizon, evidence and currentness.

## Control laws

```text
Completed
!-> OutputCorrect
!-> DesiredOutcome
!-> Standing
!-> Achievement
!-> Value
!-> Consumption
!-> RealizedBenefit

MetricGain != Improvement != Optimality != SystemImprovement
Value != Consumption != RealizedBenefit
SourcePreserved != ActuallyConsumed
ReferencePresent != CausalConsumption
ConsumerPracticeMatchesResearch != ResearchCausedPractice
```

Positive claims are allowed when their own evidence is present. Do not respond to uncertainty by collapsing everything downward. For example, a correctly resolved uncertainty can be an `ObjectiveAchievement` even when no code/product changes; a later independent beneficial consequence with adequate attribution can establish `RealizedBenefit`; pairwise dominance over the declared protected comparison scope can establish bounded `Improvement` without global optimality.

## Materialization role boundary

Physical/system materialization can play distinct roles:

- `R1 ConsequenceRepair` — repair a wrong existing consequence;
- `R2 EpistemicApparatus` — build an instrument/fixture/benchmark/measurement path needed to learn;
- `R3 ControlBoundary` — materialize an admission/currentness/authority/control distinction whose deletion permits wrong action;
- `R4 PersistenceRecovery` — preserve a deletion-vulnerable result/identity/option/source/recovery path.

`MaterializeToLearn != DeployConclusion`: successful apparatus does not establish the hypothesis/product/intervention under investigation.

Use the **strongest justified claim, but no stronger**. Missing evidence means the stronger relation remains unestablished, not that lower-level facts disappear.
