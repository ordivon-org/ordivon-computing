# OFR5 — Design Diagnosis

## The Atlas should be a map, not a new truth layer

OFR5 falsifies three tempting collapses:

```text
index != causal theory
shared law != owner-local causal history
frozen theory != current owner truth / evidence authority
```

The surviving research pattern is deliberately asymmetric. Computing may maintain a frozen navigation map to already-reconstructed theory, but current truth and action remain outside it.

## Current narrow shape

```text
compact case index
  caseId / owner / title / scope cue
  frozen revision / exact theory ref
  mechanical truth role + currentness authority
        ↓ semantic selection
read-only case hydration
  complete OFR3 causal case
  rival / attraction / falsifier / retained consequence
  counterfactual / boundary / reopen condition / exact refs
        ↓
Agent reasoning
        ↓
owner-native revalidation when current truth matters
```

### Why case-level, not field-level

OFR5's models systematically over-requested roles. A 9-field selector therefore adds a control surface without demonstrating cheaper successful cognition. The case already has a coherent causal boundary and is small enough to hydrate whole. Per-role hydration can be revisited only if a real consumer demonstrates repeated cost and reliable role selection.

### Mechanical metadata

A future Atlas observation should carry, as data rather than prose:

```json
{
  "truthRole": "non-authoritative-frozen-theory-navigation",
  "currentness": "not-revalidated-after-frozen-revision",
  "currentnessAuthority": "<owner>",
  "evidenceSufficiencyAuthority": false,
  "researchReopenAuthority": false,
  "mechanismAdmissionAuthority": false,
  "actionAuthority": false
}
```

This is analogous to ACS3's rule that mechanically knowable currentness/effect/authority facts should be projected, not reconstructed from prose.

## Why no new service is built in OFR5

The current product candidate still has an unresolved context-cost problem. The existing Harness DomainToolLoop is sufficient to demonstrate the likely integration shape, so Computing has no evidence for a new Atlas daemon, database, protocol or MCP. Git-frozen artifacts plus exact refs are enough until repeated consumers earn a live surface.
