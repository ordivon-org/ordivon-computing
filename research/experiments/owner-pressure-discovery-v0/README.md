# Owner-pressure discovery v0

C6 tests whether an Agent can discover the next useful Computer research pressure from current owner-native change without a human preselecting an architecture category.

The strong baseline receives every frozen owner-evidence card in one Provider context. The selective treatment receives only exact owner/revision/title/path metadata plus current shared claims and may inspect a bounded number of cards through a read-only Tool before submitting the same structured assessment. The hidden evaluator remains separate from both treatments.

Development contains one genuine shared-method pressure: current Harness bounded RSI can select and repair its own source target but still receives externally prepared source/evidence slices, evaluator configuration, promotion triggering and Git authority. The correct next action is a bounded selection falsifier, not an RSI controller. Other development cards are confirming evidence or owner-local churn. Frozen holdout contains no owner change that forces a new Computer experiment; a system that always invents a next layer fails the holdout.

Passing this experiment can justify only a bounded selective-evidence pressure-triage pattern inside Research. It cannot authorize a daemon, central owner-state registry, automatic Core promotion, product merge, deployment, evaluator authority transfer, or open-ended RSI.
