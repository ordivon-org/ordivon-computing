## What happened to the seven disciplines?

Again, no eighth rule is justified. The third wave instead sharpens three existing ones.

1. **D1 reader job — retain.** Game/Human demonstrate that different owner entries can already be correct exemplars and should not be normalized into one programme style.
2. **D2 pressure/judgment first — retain.** Studio's revision-`R` story and Web's owner-change story shortened both roots.
3. **D3 actor/owner/scope — strengthen.** Human response is itself a different consequence claim. Source truth, render occurrence, browser exposure, Agent observation, and human comprehension/preference/trust have different evidence owners.
4. **D4 complete causal journey — retain.** One expression journey and one publication journey carried the important boundaries while technical detail stayed behind links.
5. **D5 current before target/history — strengthen.** Owner-native publication mechanisms are part of publication authority. Web's protected-main PR/check could not be replaced by an equivalent local test. A lost merge response required reconciliation before retry, not optimism or duplicate action.
6. **D6 layered detail/link authority — retain.** Studio/Web deep systems were already strong; root contraction worked precisely because those owner-native documents remained authoritative.
7. **D7 reader consequence — strengthen.** No-change is now an explicit admissible treatment. If current documentation already passes the frozen reader task and no structural authority/currentness gap exists, a rewrite needs additional evidence rather than programme symmetry.

These refinements are recorded in `editorial-discipline-v4.json`.

## Human-comprehension boundary

This third wave gets closer to human-facing surfaces but still does **not** measure human understanding. Studio/Web can establish exact source binding, render/publication mechanics, accessibility, browser exposure, and fresh-Agent causal reconstruction. None of those observations prove what a human understood, remembered, trusted, preferred, or felt.

A future human-response programme must bind exact artifacts and scoped questions, then measure outcomes such as initial understanding, causal prediction, delayed recall, confidence calibration, trust calibration, or preference. It should not create a generic human approval bureaucracy merely because such measurements are possible.

## Rejected after FD5–FD6

- rewriting Game/Human merely to make the programme uniform;
- adding a universal Studio/Web template;
- treating published expression as current source authority;
- treating Agent or browser success as human-response truth;
- treating every owner commit as a mandatory visible Web change;
- bypassing Web protected-main PR/check because the local full gate already passed;
- blindly repeating merge after an ambiguous transport failure;
- fixing Human publication lag as an incidental side effect of a documentation experiment;
- inventing an eighth discipline instead of refining D3/D5/D7.

## Next frontier

The owner-family rewrite phase is now substantially complete. Finance and Runtime remain revision-bound candidates waiting on their active owner contractions. The next genuinely new research question is not another generic README sweep. It is the **human-response boundary**: under what conditions do different explanation/diagram/reveal-order/interaction treatments change real human understanding, recall, confidence, trust calibration, or preference, and when is such evidence worth collecting?
