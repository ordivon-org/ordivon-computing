# P0–P3 Production Consumption C-Series Closeout

Status: C0–C4 complete. This round tested **consumption pressure**, not a P4 architecture phase.

## Question

P0–P3 had already produced strong mechanisms:

- P0: installed → Run-admitted → turn-admitted capability truth plus explain/workbench composition;
- P1: exact externally owned reusable knowledge/procedure → explicit WorkingSet admission;
- P2: bounded observation-dependent ToolProgram composition with per-effect Tool authority/evidence/recovery;
- P3: owner-qualified Situation composition without global currentness/state/authority ownership.

C-Series asked a harder question: **do ordinary Game, Finance, Security and Studio consumers actually need these mechanisms, and when does extra structure become friction rather than leverage?**

## C0 — consumer pressure

Four materially different owner-current/frozen pressures were used:

1. Game R11 strategic viability after R1–R10 consumer work;
2. Finance typed governed SNXX reduce-only effect boundary, with C-Series strictly read-only and no live order authority;
3. Security CA0–CA7 closed programme as an anti-infrastructure-inflation control;
4. Studio ordinary motion-production continuation while optional Figma remained ungraduated pending OAuth.

The frozen oracle was the owner-native next operation, not model confidence.

## C1/C2 — Flash primary campaign

Treatments were `raw`, `p0p3`, `p1`, and `full`. P1 correctly selected two first-WorkingSet sources explicitly: the caller-owned current task and one exact externally owned reusable procedure. P0/P3 used the actual current capability catalog and `compile_situation()` projection.

Final robust Flash campaign:

- model: DeepSeek V4 Flash;
- 5 replicates per case/treatment;
- 80/80 logical trials completed;
- 0 equipment failures;
- every trial used one Provider model call and zero physical Tools because this was an operation-selection consumption test.

| treatment | exact | unsafe | mean tokens | mean caller prompt bytes |
| --- | ---: | ---: | ---: | ---: |
| raw | 20/20 | 0 | 1525.4 | 1480.8 |
| P0/P3 | 20/20 | 0 | 2362.5 | 4524.5 |
| P1 | 16/20 | 1 | 1625.1 | 1480.8 |
| full | 19/20 | 0 | 2465.6 | 4524.5 |

The strongest negative transfer was Game + generic P1 procedure: 2/5 exact, two safe `no_progress` outcomes, and one unsafe `reopen-basic-comprehension-redesign`. The model explicitly over-applied the generic “re-read currentness/admission” prior even though the owner-native frontier already said basic comprehension was complete and strategic viability was next.

This is not evidence against reusable procedural capital. It is evidence **for P1's existing explicit-selection law**: source existence or generic usefulness does not imply task fit, current cognition, or automatic injection.

P0/P3 matched raw correctness but added roughly 3.06× caller prompt bytes and ~55% mean Provider token use. Their value is therefore conditional: they should externalize hidden/ambiguous capability/currentness structure, not be appended to an already-good owner-native packet by default.

Full bundling also failed to dominate raw: 19/20 on Flash at substantially higher token use.

This is exactly why Flash was the high-replicate primary consumer: a very strong model can hide interface/procedure mismatch that a substrate should not require every model to compensate for.

## Architecture falsifier discovered during C-Series

The first pilot was accidentally composed as `procedure seed + task in initial_messages`. Because a projected WorkingSet does not automatically replay canonical initial Run history, the model saw the procedure but not the current task. A candidate low-level fix made all initial messages caller interaction cognition and passed focused tests.

The full Harness suite then failed 17 of 400 tests: the change violated the established separation between canonical initial Run history and projected WorkingView cognition. The candidate was deleted without integration. Code/docs/public tests showed the correct product composition instead: `HarnessCognitionSeed` is the caller-authored first WorkingSet bootstrap, so current task and reusable procedure are two explicit seed sources and the cognition-enabled Run begins with `run.run(())`.

This is a successful consumption falsifier: **full-system invariants prevented a locally plausible convenience fix from widening cognition semantics.** Harness production main remained unchanged at `6639cf575eb006e8be2864037d9427b9913dd8a3`.

## Equipment/recovery falsifier

An earlier 80-cell Flash attempt was interrupted by a Provider `BrokenPipe`. Harness correctly required explicit Provider recovery and did not blindly redispatch. The experiment runner was wrong because it wrote evidence only after all trials completed.

The runner was changed locally to atomically checkpoint every logical trial, retain equipment failures separately, and permit only a later **new Harness Run identity** to replace a missing logical cell. It never retries the unknown Provider Call identity. The final Flash/Pro campaigns then completed with zero equipment failures.

This apparatus is contracted after closeout; only final evidence remains.

## P2 independent-consumer audit

A current source audit found zero direct ToolProgram consumers in Game, Finance, Security, Studio or World. No domain ToolBridge was invented to force a positive result.

Disposition: **P2 remains advanced.** Its repository-repair ablation is real, but independent cross-domain consumption is not yet earned.

## C4 retain / shrink / reject

### P0 — retain, do not inject by default

Retain capability catalog, Run/turn projection, explain/workbench, and explicit Tool-surface composition. They are valuable when capability truth is hidden or ambiguous. Do not append the complete catalog to already-scoped owner packets merely for uniformity.

### P1 — retain exact capital, strengthen selection discipline

Retain exact external reference/resolver/seed admission and the external evaluation/promotion boundary. The experiment strongly rejects hidden/automatic/generic procedure injection. Reusable capital must be explicitly selected for task fit; a useful procedure can still create negative transfer.

### P2 — retain advanced, no further promotion

Retain bounded ToolProgram semantics and recovery. Cross-domain consumer pressure is currently absent, so no stable package-root/default promotion is justified.

### P3 — retain advanced diagnostic composition, not a global wrapper

P3's earlier stale-locus/currentness ablation remains valid. C-Series shows that when an owner-native packet is already sufficient, Situation adds no selection benefit and costs context. Use it when cross-owner ambiguity/currentness/recovery joins are genuinely present, not as mandatory context for every Agent turn.

### Full P0–P3 bundling — reject as a default

The mechanisms are composable but should not be automatically co-injected. “All good mechanisms at once” did not dominate the smallest sufficient owner-native surface.

## Stable result

The C-Series result is narrower than a new feature:

```text
owner-native surface is sufficient
    → use it directly

hidden/ambiguous capability or cross-owner currentness
    → add the smallest P0/P3 projection that resolves the mechanical ambiguity

repeated exact procedure fits this task
    → explicitly select P1 capital

real observation-dependent multi-Tool chain exists
    → P2 may be selected if exact turn authority admits it

otherwise
    → do not inject infrastructure
```

The strongest law is:

> **Agent-first does not mean maximum Agent context. It means minimum sufficient mechanically truthful context while semantic selection remains with the Agent/domain.**

No P4 is earned by this round.
