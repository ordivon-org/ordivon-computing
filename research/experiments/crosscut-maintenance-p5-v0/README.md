# Cross-cut maintenance P5 v0

P5 is a removal-first survival court for every cross-cutting feature introduced in P0-P4. It does not assume that a useful experiment deserves permanent executable residence.

The burden is intentionally asymmetric: a current active carrier must identify a current consumer, a concrete protected failure or recurring cost, why a narrower owner-native/classical mechanism is insufficient, and a reopen/deletion condition. Historical success, test count, documentation, or implementation effort do not rescue a carrier.

P5 attacks three questions.

1. **Owner temporal contracts:** do Runtime, Host, Workstation, World, and Computing actually need one generic temporal adapter, or do their existing owner-native contracts already protect the relevant failures more precisely?
2. **Unobservable staleness:** what changes can occur without a useful crosscut event, and which exact owner identities/revalidations detect them?
3. **P0-P4 survival:** after extracting stable laws and exact recovery identities, can all P0-P4 executable/test/evidence directories leave the active tree while current product-owner tests and Computing conformance remain green?

The verdict lattice is `retain-law`, `owner-local`, `evidence-only`, `delete-active`, or `inconclusive`. `retain-law` never means retain the historical P0-P4 implementation. Git history is the archive unless a unique artifact cannot be reconstructed there.

## Pre-contraction facts

At source revision `bb4c56e4d5c7d86471330f1ec413ed0f73c92e03`, P0-P4 occupied 87 tracked files, 438,877 bytes, and 10,722 text lines. Every family has an exact Git tree object recorded in `evidence/pre-contraction-inventory.json`.

The current Computer existence gauntlet already proved a much larger 317-file / 54,979-line composed contraction could preserve its tested current consumers, and specifically classified P0-P3 executable apparatus as archive candidates. P5 extends that pressure to P4 and lands only the crosscut-local contraction.

## Temporal-contract finding

The shared law is thinner than the P3/P4 adapter:

- current action must be supported by currently applicable owner evidence;
- historical evidence remains historical truth without automatically establishing current state;
- when drift matters, bind to an owner-native revision, generation, digest, freshness/revalidation rule, or exact consequence identity;
- an event may accelerate invalidation but cannot substitute for owner truth or prove that no unobserved change occurred;
- occurrence and availability are distinct when the owner exposes that distinction;
- projections do not become fact or effect authority.

The owners implement this differently. Host uses revision-fenced transitions; Runtime uses exact source/deployment/effect identities plus runtime path/image witnesses; Workstation combines bounded observations with exact binding and effect-time reprobe; World retained observation availability/reconciliation while deleting the P4-era foreign-egress/effect-path carrier; Computing uses exact Git/currentness assessment and Core evidence-scope laws. No universal temporal package is required by these current consumers.

## Contraction target

P5 removes the active `crosscut-maintenance-p0-v0` through `crosscut-maintenance-p4-v0` trees and their dedicated conformance steps. Their exact pre-contraction trees remain recoverable from Git revision `bb4c56e...`. P5 retains only compact feature dispositions, owner evidence, recovery identities, and the acceptance needed to prove the contraction itself.

## Accepted P5 result

The survival court contains 32 rows and closes with no inconclusive verdicts: 12 `retain-law`, 5 `owner-local`, 9 `evidence-only`, and 6 `delete-active`. The important contraction is representational: retained laws no longer imply retained P0-P4 executable carriers.

The real contraction removed all five P0-P4 active experiment trees: 87 files, 438,877 bytes, and 10,722 lines. All five exact Git tree objects remain recoverable from `bb4c56e...`. The post-contraction full Computing gate passed, and the independent Computer existence-gauntlet remained 28/28 after its crosscut targets were physically gone.

Gate timing is reported conservatively. Total receipt time changed from 16.49 s to 7.91 s, but the baseline link checker alone varied by ~8.30 s, so that total is not attributed to P5. Directly comparable local costs did shrink: compileall 174→34 ms, Ruff 40→12 ms, and five old dedicated crosscut test steps totaling 174 ms were replaced by the compact P5 survival test at 45 ms in the first post-contraction gate.

Owner-local action-time checks were also measured rather than assumed. Current p50 was ~1.82 ms for Runtime source revision, ~54.78 ms for Workstation temporary-equipment status, and ~157.53 ms for Runtime local health/deployment identity. These numbers do not define a universal SLA; they only falsify a need for central freshness caching merely to avoid these tested local checks.

P5 therefore closes with a smaller crosscut model: preserve owner/currentness/evidence laws, inspect the minimum relevant owner at decision time, use owner events as optional acceleration, and keep historical experiment machinery in Git rather than the active validation path.
