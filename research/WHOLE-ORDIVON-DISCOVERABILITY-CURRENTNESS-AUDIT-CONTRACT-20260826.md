# Whole-Ordivon Owner-Unknown Discoverability / Currentness Audit Contract — 2026-08-26

Status: **pre-frozen before target-query generation and Atlas retrieval trials**.

Truth role: Computing-owned cross-owner research audit design. It does not make Atlas, Computing, Host, Git, or a model the owner of another project's truth.

## 1. Question

Can a finite replacement Agent recover materially relevant prior Ordivon research when it does **not** already know the owner, repository, exact historical vocabulary, or current source location, while still distinguishing:

```text
candidate discovery
!= semantic equivalence
!= owner authority
!= currentness
!= research admission
```

The audit is specifically about the missing path:

```text
unknown prior work
→ discover candidate
→ resolve semantic owner / successor
→ re-enter owner-native current source
→ classify current / historical / superseded / unresolved
→ consume without shadow authority
```

## 5. Query families

For each of the 15 current semantic-owner targets, freeze one materially distinctive current owner-native standing/responsibility and these query treatments **before Atlas retrieval**:

### QK — owner-known / lexical-rich control

Caller knows the owner/project and may use owner name plus source-near vocabulary. This establishes that a recoverable representation exists at all.

### QU-E — owner-unknown English paraphrase

Natural English question with:

- no project/owner/repository name;
- no exact source sentence copy;
- lower lexical overlap while preserving the intended concept.

### QU-ZH — owner-unknown Chinese paraphrase

Natural Chinese question with:

- no owner/project/repository name;
- no inserted English answer-key terminology;
- the same intended concept.

This directly tests the actual Human→Agent research interaction language used in current Ordivon work against an Atlas corpus that declares no cross-language translation.

For selected transition cases, add:

### QS — semantic successor / historical vocabulary

Historical name or old representation should recover the current successor **or** explicitly remain historical without minting current authority.

### QN — negative/superseded route

A query about an old rejected mechanism/owner should recover the negative/current boundary rather than silently reactivate it.

## 6. Target generation discipline

Target standings and owner-unknown paraphrases may be generated with a bounded fresh model from current owner-native source packets **before** any Atlas query result is supplied to that model.

The generation packet must include:

- exact committed owner main revision;
- canonical README / research-root excerpt;
- explicit ban on owner/project/repository names in QU treatments;
- instruction to choose one distinctive, source-supported standing rather than invent a new claim.

Model generation is an apparatus for query formation only. The frozen target must retain its owner source path/revision and exact source excerpt so later evaluation can return to owner authority.

## 7. Retrieval instruments under test

Primary:

1. Atlas `first-look` / `first-look-many` using the existing generated owner projections + curated synthesis.

Comparators:

2. direct owner-known owner-native search — positive control, not available to the owner-unknown caller by assumption;
3. bounded whole-repository-family lexical search where necessary to distinguish an Atlas coverage failure from total source invisibility;
4. a fresh model may evaluate semantic fit between the frozen owner target and bounded candidate content, but cannot mint owner truth/currentness.

Host is continuity/handoff only. Runtime owns physical execution. Git owns exact committed bytes/ancestry. Neither is a semantic retrieval oracle.

## 8. Discovery outcome vector — no scalar success score

For each query record separately:

1. **Candidate recall** — did any top-k candidate plausibly contain the target standing or its correct successor?
2. **Rank / effort** — how deep did the caller need to go?
3. **Owner resolution** — could the candidate lead to the current semantic owner/source?
4. **Currentness legibility** — did the surface distinguish current, historical, stale, unknown, superseded, or rehomed standing?
5. **Authority escape** — was a lawful route to owner-native source preserved?
6. **False-positive pressure** — did lexically attractive but semantically wrong candidates outrank the target?
7. **Representation burden** — did success require answer-key vocabulary, manual translation, owner knowledge, or several caller-authored variants?
8. **Coverage class** — configured-owner projection, curated synthesis only, absent-owner source, historical durability source, or whole-family fallback.

Possible dispositions include:

```text
DIRECTLY_RECOVERABLE
RECOVERABLE_WITH_QUERY_AUTHORING
SYNTHESIS_RECOVERABLE_OWNER_CURRENTNESS_EXTERNAL
OWNER_KNOWN_ONLY
LEXICALLY_BLIND
CROSS_LANGUAGE_BLIND
CURRENTNESS_UNRESOLVED
STALE_OR_REHOME_MISLEADING
FALSE_POSITIVE_DOMINATED
NOT_RECOVERED
```

These are audit dispositions, not a new product schema.

## 9. Currentness oracle

Currentness is never inferred from Atlas rank, file modification time, Host Task state, or model confidence.

For every target/candidate requiring current truth:

```text
candidate
→ identify claimed owner/source
→ resolve committed current owner main / owner-native authority surface
→ compare historical/current source relation
→ classify currentness
```

A dirty/staged owner working tree is not automatically current truth. This audit source-fences committed `refs/heads/main` unless an owner-native authority explicitly defines another current state.

## 10. Prebound predictions / falsifiers

### P1 — owner-known positive control

At least most owner-known lexical-rich queries should recover a relevant Atlas candidate where that owner/result is represented. If even QK fails widely, the primary limitation is basic coverage rather than owner-unknown semantics.

### P2 — configured-owner advantage

Configured Atlas owners should have better owner/currentness legibility than non-configured owners. If not, generated owner projections are not currently buying measurable discovery/currentness value over synthesis alone.

### P3 — low-overlap fragility

Because current retrieval is lexical and does not expand semantically, QU-E should degrade versus QK when the paraphrase removes the load-bearing source terms.

### P4 — Chinese blind spot

QU-ZH is predicted to degrade sharply because current Atlas explicitly performs no cross-language translation and the synthesis corpus is overwhelmingly Latin-script. If QU-ZH performs comparably without answer-key English terms, this prediction is falsified.

### P5 — owner omission ceiling

For Computing/Harness/Security/Finance/Web, Atlas may still recover curated cross-owner synthesis mentioning them, but it should not be able to provide the same generated owner-currentness path as a configured source. If it nevertheless resolves owner currentness through another lawful path, the stronger omission claim is falsified.

### P6 — semantic successor correctness

Historical Network queries should lead toward current Interlocus or explicit historical lineage; Workstation queries must not fabricate a current standalone owner; Post-Host must remain historical; current Normative/Interlocus source rehomes should outrank stale Atlas README topology when currentness is adjudicated.

### P7 — synthesis/currentness separation

Curated synthesis may provide excellent conceptual recovery while still requiring owner-native currentness re-entry. If synthesis text is treated as current owner truth by the audit apparatus, the audit fails its own authority contract.

## 11. Admission ceilings

This audit does not pre-authorize:

- adding all missing owners to Atlas;
- semantic embeddings/vector search;
- cross-language translation in Atlas;
- an LLM query-router;
- a global owner registry;
- a new Research service/database/MCP;
- automatic owner inference or novelty admission;
- deleting lexical first-look if it remains a strong cheap control surface.

The result should first identify **which relation is missing**: source coverage, query translation, semantic retrieval, owner resolution, currentness, authority escape, or representation.
