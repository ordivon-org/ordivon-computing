> How many Ordivon projects or research topics are named in the prose?

> Which load-bearing distinctions from the broader Ordivon research portfolio can a fresh finite consumer recover from the Book strongly enough to make correct judgments across new domains, which research remains correctly owner-local, and which cross-cutting models are only implicit enough to create future rediscovery risk?

Therefore:

```text
TextualMentionCoverage != DecisionModelCoverage
ProjectMention != ResearchAssimilation
OwnerSpecializationAbsentFromBook != BookFailure
InferableFromBook != ExplicitlyCompressedInBook
```

## 5. Functional transfer test — named domains omitted from prose do not imply missing foundations

A keyword scan of the exact Book found little or no direct Security/Game/SCD/Computational-Possibility/Interlocus naming. That was intentionally treated as weak evidence.

A stronger test gave three fresh Agents **only** the exact five-chapter Book and twelve new cross-domain cases. No source map, owner repository, Task chronology or Tool access was supplied.

Accepted Runs:

- `harness-run:book-v05-crossdomain-v2-1-1787593067860`
- `harness-run:book-v05-crossdomain-v2-2-1787593072877`
- `harness-run:book-v05-crossdomain-v2-3-1787593078502`

Each used one model call, zero Tools and zero conclusion corrections. All three recovered all twelve intended judgments:

1. exact projection does not establish judgement-relative semantic sufficiency;
2. semantic validity does not establish computational possibility;
3. Runtime Job success does not establish domain consequence;
4. Message delivery does not establish cognition;
5. completion/artifact/citation does not establish realized benefit;
6. joint Human-Agent capability does not establish retained Human capability;
7. adversary-controlled sensor evidence does not become world truth;
8. mechanical playability does not establish Player Value;
9. an owner revision can legitimately yield a public Web NO_OP after relevant revalidation;
10. a prior can be split/narrowed when only one support clause is threatened;
11. an all-green observation basis can justify changing/expanding the pressure interface when blindness is plausible;
12. reachability/capability does not create authority.

All three returned `bookSufficientForAllTwelve=true`.

Self-reported weakest cases differed (`[9,2,7]`, `[9,10]`, `[8,9]`) rather than identifying one systematic domain failure.

The first attempted carrier used unsupported `uniqueItems` in the current Harness structured-result profile and failed before any model call. It is carrier evidence only.

### Consequence

This test strongly falsifies the naive proposal:

```text
Security/Game/Web/SCD/CP not named much
-> Book lacks those domains
-> add one chapter per domain
```

The current evidence instead supports:

```text
Foundational decision geometry transfers
+
owner/domain specialization remains external
+
comparative cases can improve evidence/readability without becoming new foundations
```

## 7. External solution-domain pressure

This audit does not claim that memory, learning, automation allocation, testing or evaluation were invented by Ordivon.

Mature organizational-memory work separates acquisition, retention and retrieval and explicitly discusses use/misuse of retained information. Organizational-learning work characterizes learning as routine-based, history-dependent and target-oriented, with inferences encoded into routines. These lines support the Book's `Preserved != Environmentalized` boundary but also show that a compact Book is not expected to duplicate organizational theory.

Human-machine automation research likewise predates Ordivon responsibility-relative primacy. Parasuraman, Sheridan and Wickens separate automation across information acquisition, analysis, decision/action selection and action implementation, and emphasize that automation changes human activity and can create new coordination demands. This supports decomposition of historical role bundles while constraining novelty claims.

NIST AI RMF 1.0 supplies a modern operational pressure on value/evaluation: measurement is contextual, uncertainty-aware, repeated during operation, benefits from independent review, and can lead to recalibration, mitigation or removal. The framework also warns that metrics can be oversimplified or gamed and that laboratory measurements can differ from real-world risk. This is consistent with `MetricGain != SystemImprovement` and `EnvironmentChanged != BenefitEstablished` but does not supply Ordivon's owner-specific result semantics.

Severe-testing traditions similarly make a useful negative point: evidence quality depends on whether a test had a serious chance to expose error, not only on the amount of confirmatory material. The Book's generic challengeability can infer this, while current PAL research gives a more explicit internal `SupportProvenance != ChallengeProvenance` formulation.

Classical computability/complexity and programming-semantics traditions already separate questions of meaning/specification from what is computationally achievable and from one concrete execution. Therefore the Book should not absorb SCD or Computational Possibility into a supposed new universal theory merely because `Meaning != Possibility != Realization` is useful cross-owner orientation.

### Game — interactive / constructed Reality

What a case adds: a Reality can be intentionally constituted and still require owner/evaluator separation; the human player is claim-relative evidence, not a universal gate.

### Web — public encounter Reality

A source revision creates a review obligation, not an automatic public mutation. Exposure is not comprehension. Publication requires source-currentness revalidation and can legitimately end in NO_OP.

### Media — meaning/expression mediation

Media proves that owner truth and observer-relative expression can be separated at production scale. Its aesthetics/narrative/culture programme is much richer than the Book and should remain so.

What a case adds: expression can change human/Agent encounter without becoming truth authority; human experience claims need the actual human-response relation.

### Human — joint intelligence and timescale Reality

Human-AI research distinguishes independent, situated, joint, verification, transfer and recovery capability. Joint output does not establish internalized Human capability.

What a case adds: responsibility-relative placement has a time/learning consequence; delegating work can change which capabilities the Human retains and which failures the joint system can recover from.

However, current evidence does **not** establish a Chapter 6. The missing object may be a section/bridge that sharpens Chapter 3's consequence tail or a companion essay on `What counts as improvement?`.

### 9.2 Challenge quality / recursive improvement — real but not mature enough for a new chapter

Book strongly preserves challengeability. Current PAL research adds deeper distinctions:

Fresh Book-only consumers infer the correct behavior, but the explicit challenge-quality model is less stable (2/3 called it explicit, 1/3 not). Current Computing also lists key recursive-improvement questions as research-only.

Therefore this is a **future Chapter-6 candidate pressure**, not current chapter standing.

### 9.3 Meaning / Possibility / Realization — useful orientation, specialist theories remain separate

Atlas worldview's compact law:

```text

!=
```

is powerful and fresh Book consumers recover it. Yet the exact Book does not consistently make the triad explicit enough for every consumer to identify it as a named model.

This is best treated as a compact cross-owner orientation/bridge, not a new chapter. SCD and Computational Possibility have rich independent owner theories that the Book should not duplicate or silently absorb.

## 11. Book v0.5 destination adjudication

### Do not mutate the five approved core chapters merely to increase topical coverage

The current five-chapter Book has stronger cross-domain functional coverage than textual inventory suggests. A broad rewrite would risk duplicating specialist owners and weakening the compact world-model geometry.

### Do not create Chapter 6 yet

Two cross-cutting frontiers could eventually earn it:

1. **Improvement / Value / Benefit** — What does it mean for a finite-intelligence system to become genuinely better rather than merely produce more output, metrics, capability or internal consumption?
2. **Recursive Improvement / Challengeability** — How can adaptation increase capability without destroying the future ability to falsify the basis under which improvement is judged?

The first has mature internal semantic standing but has not yet demonstrated that a separate chapter changes consumer decisions beyond what Ch1/3/5 imply. The second remains partly open research.

### Domain companion is useful, but its current role is evidence/readability rather than missing decision capability

A future Media `Book Domain Companion` could use Finance, Runtime/Host/Harness, World, Security, Game, Web, Media and Human as comparative cases. It would answer:

> How do the same five foundational distinctions look when Reality itself has different ownership, adversariality, observability, consequence and human-relation structure?

But the current fresh-consumer evidence says this companion is not required to make the twelve tested judgments correctly. Therefore it should be admitted only as a **reader/transfer/evidence product**, not as repair of a broken core model.

The next truthful Media step is to test whether such comparative cases materially improve Human/fresh-Agent comprehension, transfer confidence or retention. Until then, keep the domain map in this Computing audit rather than adding new permanent Book source bindings and currentness debt.

### Current Book change decision

```text
Five core chapters: NO_CHANGE
Chapter 6: NOT_ADMITTED
Domain companion: CANDIDATE / reader-transfer evidence not yet measured
Result/Value compact integration: strongest targeted revision candidate
Challengeability/recursive-improvement chapter: OPEN RESEARCH CANDIDATE
Meaning-Possibility-Realization bridge: useful compact orientation candidate, not new theory
```

## 12. Reopen conditions

Reopen core Book coverage when at least one occurs:

- a fresh Book-only consumer repeatedly makes a consequential owner/domain error that a stable cross-cutting research result prevents;
- the Result/Achievement/Value map produces a prospective decision delta that current Ch1/3/5 cannot reliably recover;
- challenge-quality / recursive-improvement research reaches stable cross-owner standing and changes future decisions beyond existing challengeability;
- Human/domain readers show that the compact foundations transfer poorly without comparative cases;
- a specialist owner exposes a foundational distinction that cannot be expressed by current Reality/Representation/Action/Currentness/Environmentalization geometry without semantic loss;
- a stronger mature external theory collapses an apparent Ordivon-specific gap.

Do not reopen because more projects, Foundation numbers, Tasks or research files exist.

## 13. Bottom line

The current Book is **not** a compressed encyclopedia of Ordivon research, and it should not become one.

At the current evidence cut it is better described as:

> **a compact, unusually transferable finite-intelligence decision model whose five foundational distinctions already generalize across much more of Ordivon's domain research than explicit chapter vocabulary suggests.**

Its present weakness is not broad theoretical incompleteness. The main weaknesses are:

1. several mature cross-cutting distinctions remain **inferable rather than explicitly compressed**, especially Result/Achievement/Value/Realized Benefit;
2. rich domain evidence is **invisible to the reader**, limiting explanatory texture and transfer confidence even though fresh Agents can infer the right decisions;
3. recursive-improvement/challenge-quality research remains **open enough that promoting it now would outrun the evidence**;
4. Human continuous-reading/retention/transfer evidence for the Book remains much thinner than Agent structured-consumer evidence.

Therefore the mature v0.5 move is not `add more chapters`. It is:

```text
protect the five-chapter core
+ expose the true implicit compression debt
+ test a comparative domain companion as a reader/transfer intervention
+ earn any Chapter 6 through a new decision failure, not symmetry
```

The confirmatory A/B used five accepted fresh Agent replicates per arm over 22 frozen classification/transfer cases:

```text
Book only      = 110 / 110 correct
Map + Book     = 110 / 110 correct
accuracy delta = 0
```

The explicit compact map added 776 prompt tokens/run and produced no fresh-Agent decision-correctness gain. Therefore the earlier status:

```text
Result/Value compact integration = strongest targeted revision candidate
```

is now superseded for the tested Agent-correctness claim by:

```text
Result/Value core Book integration = NOT_ADMITTED_FOR_AGENT_CORRECTNESS
Five-chapter core                   = NO_CHANGE
Chapter 6: Result / Value           = NOT_ADMITTED
```

A post-primary exploratory multi-label reconstruction challenge did find bounded representational value: Book-only produced 28 label errors across 24 composite-case replicates, while Map+Book produced 14; exact composite cases moved from 10/24 to 12/24. The map eliminated observed missing `BOUNDED_IMPROVEMENT` / `CONSUMPTION` and extra `BOUNDED_OPTIMALITY` / `PROSPECTIVE_VALUE` errors in that workload, but did not eliminate the shared tendency to infer lifecycle `COMPLETED` from artifact existence/production.

This does **not** reverse the confirmatory admission decision. It establishes a narrower standing:

```text
Decision repair value             = not demonstrated
Explicit reconstruction value     = demonstrated in bounded exploratory Agent workload
Human pedagogical/retention value = unknown
Universal default injection       = not earned
Operation-specific Result audit reference = justified
```

The resulting Book frontier is therefore more specific than the original audit: do not expand the core because a richer taxonomy exists. Test representations against the target consumer, timescale and operation. Reopen Media only on a reproduced Human/long-delay/lower-capability/ordinary-path transfer deficit or another consequential consumer failure that the compact representation prevents.
