# Computer P0–P1 Core A-Series Audit

Date: 2026-08-01
Baseline: `be5fe779267f0225dd37c570932c7d71ee5223a7`

This audit applies the complete Core foundations to Ordivon Computing itself. The decisive tests are A1, A10, A11, A13, A14, and A15: reuse mature mechanisms; bind claims to evidence; make every durable constraint prove net acceleration; create no new layer without an unowned non-bypassable responsibility; preserve concise history while deleting active machinery; and keep judgment above checks.

| Candidate constraint or structure | A-series decision | Protected failure | Recurring cost | Review or deletion condition |
|---|---|---|---|---|
| `portfolio.json` as the only mutable research-status source | **Retain, narrow** | Contradictory Ready Frontiers and hidden WIP | One small JSON edit plus generated view | Delete or replace if it creates more maintenance than status drift; prose must not copy its fields |
| Two-line WIP limit | **Retain as a judgment aid** | Parallel research fragmentation and unfinished evidence | Defers otherwise valid work | Override or revise through participant judgment; delete if measured opportunity cost exceeds avoided fragmentation |
| Root and overview documents copying active line IDs | **Delete** | None beyond convenience; copies already drifted | Repeated synchronization and misleading Context | Keep only links to the generated portfolio |
| Durable page and graph node for `active`, `ready`, or `blocked` questions | **Admit narrowly** | Live work without a stable hypothesis, falsifier, or dependency relation | One page and one graph entry per live question | Do not require historical completed or superseded items to regain graph presence |
| Exact external product observation on externally owned live questions | **Admit narrowly** | Computing claims a stale product state while product code has advanced | One revision and snapshot update when interpretation changes | Remove if automated product-derived evidence makes the local observation redundant |
| Immutable Harness System Snapshots | **Admit** | Live Harness claims detached from exact Host code and Artifact | One append-only manifest per material closure | Never mutate; supersede only with later evidence; OH4 supersedes but does not rewrite OH3 |
| Protocol release manifest and Git tag | **Admit** | Package version, schemas, vectors, stability, and consumer evidence become ambiguous | One manifest per release and one Git tag | Delete custom release metadata if a mature package registry provides the same immutable binding |
| Profile-level protocol stability and explicit limitations | **Admit** | A bounded profile is mistaken for a universal ontology | Small release metadata | Remove fields that have no consumer decision or migration effect |
| JSON Schema plus implementation differential corpus | **Admit on protocol paths** | Structural Schema silently diverges from Python or TypeScript acceptance | One dependency and milliseconds of tests | Delete duplicated checks if one machine-readable source generates all structural validators |
| Cross-repository consumer gate | **Admit only on protocol changes** | Computing passes while Host or Game rejects the released contract | Checkout plus bounded Host/Game contract tests | Narrow or delete when a registry or package release system supplies equivalent consumer verification |
| New central research service, graph database, protocol daemon, or policy engine | **Reject under A1/A13** | No unowned non-bypassable responsibility has been reproduced | Permanent service, state, migration, and operational burden | Reconsider only after the file/Git/CI design fails on a real trajectory |
| Immediate independent Protocol repository | **Defer** | Current co-versioned experiment-to-protocol path still has value | Multi-repository release coordination | Reconsider after independent release cadence or another materially different consumer |
| Universal abstention or control platform | **Reject before experiment** | Existing Host state and static policy have not yet been falsified | New authority and interruption surface | Reconsider only after paired trajectories demonstrate a cross-workload invariant |

## Result

The Computer architecture remains a Git- and file-backed epistemic, experimental, and protocol-forge repository. P0–P1 adds no daemon, database, central scheduler, or new authority layer. New constraints are limited to deterministic checks at the exact boundaries where recurring drift was reproduced, and each has an explicit deletion condition.
