# 09 — Ordivon Insertion and the R3 Gate

## R2 architectural conclusion

R2 establishes that interpretation is distributed across component-owned
boundaries. Ordivon needs enough evidence to compare those interpretations, but
it should not become the owner of every protocol, URL, cache, browser, template,
query, or command parser.

```text
Host owns semantic intent and Effect admission.
Runtime owns trusted-local execution and Artifact truth.
World-native components own external path, protocol, provider, browser, cache,
Tool, and resource facts.
Security owns adversarial hypotheses and evaluation.
Game owns designed hidden truth and deterministic replay.
Classical parsers retain their native semantics.
```

## Host implications

Host should preserve:

- participant Goal and Task;
- candidate versus admitted Effect;
- exact Tool and World Binding;
- external data versus trusted instruction;
- typed arguments rather than reconstructed command strings where possible;
- `UNKNOWN` and reconcile-before-redispatch;
- model, Provider, Host, Harness, and policy profile in evaluation evidence;
- accepted completion based on domain verification.

Host should not infer that a safe model response means an external parser path is
safe.

## Runtime implications

Runtime should support:

- exact Workspace and source revisions;
- disposable parser, build, and test environments;
- process and Job identity;
- raw and canonical Artifact capture with bounded size;
- generated Tool source, dependency, binary, and test evidence;
- local process-tree and residual cleanup;
- no automatic adversarial interpretation of parser differences.

A later differential harness can run on Runtime without becoming Runtime Core.

## World implications

World-native modules and providers may expose:

- negotiated protocol, connection, transition, endpoint, and route;
- exact provider and intermediary chain where available;
- URL, origin, site, host, path, and request projection;
- field, cache, media-type, browser, and content observations;
- generated Tool deployment and external identity facts;
- provider-native Receipts, callbacks, cache purge, and object state;
- observations conditioned on method, revision, path, time, and invalidation.

R2 does not justify one central raw-request journal or canonical request object.

## Security implications

Security may own:

- attacker and defender profile;
- interpretation-differential hypothesis;
- relationship among policy meaning, executor meaning, and evidence meaning;
- bounded primitive and chain classification;
- repeated, adaptive, and held-out Trials;
- evaluator-integrity outcomes;
- tactical, operational, strategic, containment, recovery, and residual outcomes.

Security should consume native parser and World evidence instead of copying all
state into a generic security database.

## Game implications

Game can provide an early deterministic laboratory with:

- hidden authoritative parser outputs;
- front-end and back-end components with controlled differentials;
- cache keys and variants;
- actor-specific observations;
- browser and Agent interpretation layers;
- Red/Blue policy adaptation;
- exact reset and counterfactual replay;
- no public target.

This is useful for strategic and evaluator research. It is not a substitute for
later real-protocol fidelity when the conclusion depends on actual parser or
network behavior.

## Candidate future experiment

A minimal R2-derived experiment should not begin as an offensive range. It can
compare two or more mature parser stacks inside an owned local topology:

```text
frozen representation corpus
→ exact front parser
→ exact translation
→ exact back parser
→ typed projection comparison
→ security-boundary oracle
→ independent Effect oracle
→ minimization and regression
```

Initial outcomes:

- differential exists but has no security consequence;
- differential creates a bounded primitive;
- existing strict parser or configuration removes it;
- topology simplification removes it;
- custom Ordivon abstraction adds no value and is deleted.

## Constraint audit

### Retain

- strong attacker assumptions;
- model/Host policy as a bound variable;
- exact component revisions;
- native authority and evidence;
- typed Effect and `UNKNOWN`;
- independent world verification;
- generated Tool provenance;
- residual cache, Tool, body, and credential closure.

### Do not promote yet

- universal canonical representation;
- global parser graph service;
- generic Web firewall;
- central raw traffic repository;
- new HTTP or URL parser;
- universal sanitizer;
- generic injection detector;
- mandatory approval for reversible local parser analysis;
- assumption that one parser differential implies exploitable impact.

### Deletion tests

Delete or localize a proposed shared component if:

- standards-conformant native parsers and typed adapters solve the failure;
- it becomes another disagreeing interpreter;
- it duplicates provider or Runtime evidence;
- only one product consumes it;
- it cannot preserve raw and executed representations accurately;
- it adds no measurable transfer, recovery, or attribution value;
- its operational friction exceeds avoided loss.

## R3 route

R3 should study **network naming, routing, transport, encryption, and partial
failure**:

```text
DNS names, records, resolvers, caches, and DNSSEC
IP addressing, NAT, and endpoint identity
BGP and inter-domain route propagation
TCP sequencing, retransmission, and stream semantics
UDP and datagram boundaries
TLS endpoint authentication, confidentiality, integrity, and resumption
QUIC connection IDs, streams, migration, and 0-RTT
proxies, VPNs, tunnels, and service meshes
timeouts, retries, duplicate Effects, and UNKNOWN
path observation versus application outcome
Agent path discovery, switching, and defensive deception
```

The central question is:

> What can a network observation prove about identity, delivery, execution, and
> world consequence—and what remains unknowable without endpoint and application
> evidence?

R3 remains standards-led and non-operational. It may analyze real routing,
protocol, and outage chains, but it will not provide intrusive network actions or
third-party attack procedures.

## Completion criteria

R2 is complete when:

- representation, parsed structure, canonical form, semantics, and authority are
  distinct;
- protocol, URL, field, content, cache, application, and model differentials fit
  one typed framework;
- RFC 9931 optimistic-transition risk extends the model beyond traditional
  framing disagreement;
- Agent capability and platform policy behavior are evaluated separately;
- defense emphasizes parser reduction, typed boundaries, strict rejection,
  independent evidence, and residual closure;
- no universal Ordivon parser or policy layer is promoted;
- R3 has a concrete standards and evidence question.

These criteria are satisfied by this study.
