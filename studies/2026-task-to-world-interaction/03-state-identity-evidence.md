# 03 — State, Identity, Evidence, and Uncertainty

## Identities that must remain distinct

```text
Goal / Task / Attempt / Effect / Dispatch
logical target / participant / authority
endpoint / path observation / transport session
request or message delivery
provider operation / body or service generation
Receipt / Artifact / Observation / Claim / Verification
```

Unification means correlation, not collapse.

## Conditioned evidence

An external result may depend on:

- provider and physical execution generation;
- endpoint, route, egress, region and DNS result;
- authenticated identity, credential and policy revision;
- session, cookie, locale, time and method;
- capability, build, model and Tool revision.

Historical evidence can remain authentic while no longer supporting a current
Claim. The system must distinguish valid, conditionally valid, expired,
superseded, contradicted and unresolved evidence.

## Uncertainty states

A useful external interaction cannot be reduced to success/failure:

- proposed or bound;
- sent or delivery unknown;
- accepted;
- queued or running;
- replied or response lost;
- semantically succeeded;
- failed or rejected;
- cancelled or compensation pending;
- compensated;
- outcome unknown.

Retries occur only after reconciliation or an explicit duplicate-safe policy.

## Authority

Physical capability, authenticated identity, delegated authority and allowed
consequence remain separate. A reachable provider or available Sandbox does not
imply permission to use every capability or produce every external effect.
