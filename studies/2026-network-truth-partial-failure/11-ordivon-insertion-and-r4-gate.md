# 11 — Ordivon Insertion and the R4 Gate

## R3 architectural conclusion

R3 validates the existing thin split:

```text
Host
  participant purpose, Task, Effect, Binding requirements, retry and completion

Runtime
  local process, socket, Workspace, Job, stream, Artifact, and timeout truth

World-native modules and providers
  DNS, route, path, connection, TLS, proxy, body, provider object, Receipt,
  callback, and external Effect observations

Security
  attacker position, Campaign, deception, contradiction, containment, recovery,
  and evaluator interpretation

Game
  designed hidden network truth, actor observations, reset, and replay
```

No repository should become a universal duplicate of all network telemetry.

## Host implications

Host should preserve:

- semantic Effect identity across attempts and paths;
- explicit `UNKNOWN` after ambiguous communication failure;
- path and service requirements for the Task;
- alternate Binding as a new conditioned decision;
- model/Provider/Host/Harness policy profile in evaluation;
- bounded retry budget and reconciliation;
- participant authority for changed consequence;
- accepted completion based on domain verification.

Host should not equate DNS success, socket connection, TLS handshake, or response
status with completed work.

## Runtime implications

Runtime should provide:

- local resolver, interface, route, proxy, VPN, socket, and process observations
  when requested;
- exact command, Tool, source, and dependency revision;
- bounded raw and structured network Artifacts;
- disposable measurement environments;
- timeout, cancellation, process-tree, and residual local evidence;
- no strategic interpretation of network anomalies.

Network measurement Tools can run on Runtime without becoming Runtime Core.

## World implications

World-native providers may expose:

- resolver identity, DNS answer, DNSSEC state, TTL, and cache condition;
- BGP/RPKI observations and route vantage where available;
- address family, interface, NAT, proxy, VPN, and tunnel relations;
- transport, connection, path, migration, fallback, and endpoint facts;
- TLS reference identity, certificate, ALPN, terminator, and resumption facts;
- provider-native request, Receipt, callback, external object, and reconciliation;
- observation method, time, freshness, and invalidation.

R3 does not prove these belong in one service or stable universal schema. Most
remain Adapter/provider-local until two materially different consumers require a
shared relation.

## Security implications

Security may own:

- attacker network position and resources;
- naming, routing, endpoint, replay, delay, and observer hypotheses;
- attack and defense chain relations;
- multi-vantage contradiction interpretation;
- forced fallback and path-deception evaluation;
- tactical, operational, strategic, information, containment, recovery, and
  evaluator-integrity outcomes;
- Campaign-level residual requirements.

Security should not become a DNS resolver, BGP monitor, VPN, proxy, service mesh,
or SIEM.

## Game implications

Game can model:

- authoritative DNS and routing truth;
- actor-specific resolver and route views;
- path loss, delay, duplication, and migration;
- TLS identities and compromised endpoints;
- proxy and VPN topology;
- retry and callback behavior;
- Red/Blue adaptive policies;
- deception and monitor compromise;
- exact reset and counterfactual replay.

Game models strategic structure. Real protocol fidelity remains necessary when
the conclusion depends on actual implementation behavior.

## Candidate future experiment

A later owned-range network experiment can freeze:

```text
one semantic Effect
one client Host and Runtime
one provider endpoint
several controlled DNS/path/transport/TLS conditions
one independent provider or object verifier
```

Then compare:

- normal path;
- stale DNS;
- route/path change;
- IPv4/IPv6 divergence;
- VPN or proxy change;
- QUIC fallback;
- response loss after commit;
- duplicate retry;
- endpoint replacement;
- observer disagreement.

The experiment should ask whether existing Host, Runtime, provider, and narrow
World observations suffice. A new shared World object is admitted only after a
reproduced unowned failure.

## Constraint audit

### Retain

- capability/consequence separation;
- maximal bounded attacker assumptions;
- model and Host policy as configuration evidence;
- component-native network facts;
- stable Effect and `UNKNOWN`;
- reconcile-before-redispatch;
- explicit fallback Binding;
- independent outcome verification;
- residual external closure.

### Do not promote yet

- universal network truth service;
- global route or DNS database;
- custom resolver, BGP stack, VPN, proxy, or transport;
- mandatory packet capture for every Task;
- central path policy engine;
- IP-based universal Agent identity;
- always-on approvals for reversible local measurement;
- assumption that encryption implies trusted endpoint behavior.

### Deletion tests

Delete or localize a proposed shared component if:

- mature native systems and Adapter-local observations resolve the failure;
- it copies telemetry without changing decisions;
- one consumer uses it;
- it cannot express vantage and freshness;
- it promotes path evidence into Effect truth;
- it becomes a high-friction central control plane;
- reconstruction and rotation are cheaper than maintaining it.

## R4 route

R4 should study **real cross-layer defect and vulnerability chains** using the
R0–R3 grammar:

```text
necessary Web/network property
→ trust and interpretation tension
→ weakness and concrete vulnerability
→ network and identity preconditions
→ exploit primitive
→ cross-layer attack chain
→ adaptive Campaign
→ defensive breakpoints
→ recovery and residual proof
```

Candidate case families:

- SSRF joined with DNS, redirects, internal identity, and cloud metadata;
- request smuggling joined with proxy trust, cache, or authenticated connection;
- cache poisoning joined with browser or Agent active interpretation;
- route/DNS manipulation joined with endpoint identity failure;
- TLS terminator or supply-chain compromise using valid cryptographic identity;
- timeout and retry manipulation causing duplicate financial or infrastructure
  Effects;
- prompt injection joined with browser session, generated Tool, path switching,
  and delegated Tokens;
- multi-Agent propagation through trusted messages and network services.

R4 remains non-operational. It will use official incident evidence and causal
reconstruction without exploit payloads or third-party procedures.

## Completion criteria

R3 is complete when:

- naming, routing, location, transport, channel identity, application response,
  and Effect are distinct;
- DNSSEC, RPKI, TLS, and QUIC guarantees and omissions are explicit;
- NAT, proxy, VPN, fallback, migration, and multi-vantage observations are
  represented;
- timeout, replay, retries, and residual state connect to stable Effect identity;
- model/Host refusal is recorded without weakening the attacker model;
- no universal network control layer is promoted;
- R4 has a concrete cross-layer case method.

These criteria are satisfied by this study.
