# 06 — Ordivon Insertion and Next Route

## R0 architectural conclusion

R0 changes Ordivon's analysis discipline but does not yet justify a new shared
runtime service, Protocol object, or production rule engine.

The durable result is a responsibility map and admission test:

```text
World supplies external capability and authoritative native facts.
Security supplies adversarial meaning, Campaign hypotheses, and evaluation.
Host owns participant purpose, Tasks, Effects, and accepted completion.
Runtime owns trusted-local execution truth.
Game supplies designed rules, hidden state, replay, and counterfactual Worlds.
Classical mechanisms retain protocol, process, isolation, identity, and storage authority.
```

## Ordivon World implications

World should eventually be evaluated as the carrier of externally realized
capability, not merely a passive provider directory or one correlation journal.
Candidate responsibilities include:

- current target, endpoint, path, identity, session, provider, and body facts;
- network and service observations with freshness and invalidation;
- Tool and Adapter instances, generated-Tool provenance, build environment, and
  bounded deployment;
- external Effect execution facts, provider-native Receipts, callbacks, and
  result reconciliation;
- environment mutation, snapshot, reset, destruction, and residual evidence;
- independent evidence surfaces consumable by Security.

R0 does not prove that all of these belong in one service or schema. Most should
remain in native modules and providers until a shared responsibility survives a
deletion test.

## Ordivon Security implications

Security should consume World facts without replacing them. Candidate Security
responsibilities include:

- Actor, objective, Campaign, and opponent-policy identity;
- attack and defense causal-graph hypotheses;
- authoritative-world versus actor-observation separation;
- deception and counter-deception interpretation;
- tactical, operational, strategic, information, containment, recovery, and
  evaluator-integrity outcomes;
- repeated and adaptive Trial families;
- residual closure requirements for one admitted Campaign.

Security should not become a scanner, SIEM, network controller, Runtime, Tool
registry, or universal fact database.

## Host implications

Host must preserve:

- participant purpose and authority;
- stable Task and Effect identity;
- the distinction among external data, candidate instruction, and committed
  action;
- current World and Tool bindings in compiled Context;
- `UNKNOWN` and reconcile-before-redispatch;
- accepted completion under a domain verifier.

Prompt-level defenses cannot replace consequence admission and world
verification.

## Runtime implications

Runtime should continue to provide:

- isolated, observable, recoverable local execution;
- exact source and Workspace state;
- process identity and streams;
- Artifact and exit evidence;
- generated Tool build and test environments when requested by an owning Host or
  World workflow;
- no adversarial interpretation of process activity.

## Game implications

Game is the preferred early substrate for:

- authoritative hidden world state;
- actor-specific observations;
- controlled parser, identity, network, memory, Tool, and evaluator conditions;
- repeated seeds and counterfactual replay;
- adaptive Red/Blue policies without public-world consequence.

High-fidelity World integration should follow only when simulation omits a
causal variable that changes the research conclusion.

## Derived design constraints

### C1 — no vulnerability-only architecture

A product feature must name the failure trajectory and world consequence it
prevents, not merely a vulnerability category.

### C2 — no central truth by convenience

Do not copy Host, Runtime, provider, Game, and Security state into one World or
Security database merely to simplify queries.

### C3 — evidence is conditioned

Observations bind method, identity, path, revision, time, and invalidation.

### C4 — generated Tools are capabilities, not trusted products

Treat generated code as a candidate Artifact until built, tested, scoped, and
observed in a bounded environment.

### C5 — attack and defense are adaptive distributions

Later evaluation must include repeated trials, held-out attacks or opponents,
policy changes, and cumulative success.

### C6 — patching and Campaign closure differ

Recovery includes identities, sessions, bodies, Tools, memories, external
objects, observer integrity, and residual uncertainty.

### C7 — constraints follow consequence

Keep reversible private analysis broad. Bind shared, durable, costly, or
irreversible effects to current World scope and participant authority.

### C8 — no offensive implementation before the experiment boundary

Deep mechanism knowledge may advance first. Executable attack work remains
inside a separately admitted owned range with independent management,
observation, stop, reset, and residual proof.

## R1 admission

R1 is admitted as a knowledge study because Web identity and delegation are the
first major join between useful connectivity and dangerous ambient authority.
It should study:

```text
URL, origin, site, and network endpoint
browser principal and process boundaries
cookies, sessions, tokens, and automatic attachment
same-origin policy and cross-origin mechanisms
CSRF and confused deputy
OAuth-style delegation and non-human identity
browser Agents and external-data hijacking
identity evidence, revocation, and residual sessions
```

R1 remains non-operational. It should produce causal models, standards-based
explanations, and architecture implications before any controlled experiment.

## Completion decision

R0 is complete when:

- the vocabulary distinguishes all cited cases;
- the graph represents attack, defense, evidence, recovery, and adaptation;
- Agent additions are separated into unchanged, amplified, composed, rewritten,
  and unproven new responsibilities;
- no production layer is promoted without experiment evidence;
- R1 has a concrete question and evidence route.

Those criteria are satisfied by this study. Future contradictions revise the
study; they do not preserve the framework by default.
