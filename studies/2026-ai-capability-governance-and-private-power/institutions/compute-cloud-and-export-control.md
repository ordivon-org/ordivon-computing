# Compute, Cloud, and Export-Control Layer

Observed through: 2026-08-01

## Why this is a separate governance layer

Model policy is only one control point. Advanced AI capability depends on:

```text
accelerator design and fabrication
high-bandwidth memory and packaging
cloud clusters and datacentres
energy and networking
model weights and training code
identity, billing, sanctions and trade compliance
API and distribution channels
```

Compute is unusually governable because it is comparatively detectable,
excludable, quantifiable, and concentrated. Cloud and chip Providers can act as
securers, record keepers, verifiers, licensing points, and enforcement agents.

## State-provider coalition

Export control, sanctions, procurement, national-security agreements, and allied
technology packages can require private firms to identify customers, restrict
regions, preserve records, apply access controls, or refuse service. These powers
may prevent proliferation or unauthorized military use while also expanding
surveillance, geopolitical exclusion, and incumbent advantage.

## Open-weight interaction

Downloading weights weakens upstream request-level control but does not eliminate
compute governance. High-capability use may still depend on a small number of
hardware, cloud, colocation, network, and financing actors. Local inference can be
technically possible while large-scale fine-tuning or deployment remains dependent.

## Ordivon measurement implication

Future exit studies should measure at least:

```text
weight portability
inference hardware availability
cloud substitutability
state and Artifact portability
Tool and identity portability
region / sanctions eligibility
cost and performance after migration
```

“Can download the model” and “can continue equivalent work” are different claims.
