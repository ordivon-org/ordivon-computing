# Application and falsifiers

## 1. Correction to source-level audit

A source audit should no longer treat the repository as a set of legitimate structures whose implementation must be checked. It begins with two independent questions:

```text
legitimacy audit
Should this structure remain active?

implementation audit
If retained, is its ownership and behavior correct?
```

Implementation correctness cannot rescue an illegitimate structure. A perfectly concurrent compatibility layer with no consumer remains debt. A fully tested gate that measures no consequential property remains ceremony.

## 2. Station Zero examples

| Existing structure | Default disposition | What could rescue it |
|---|---|---|
| Global percentage coverage blocker | delete as a blocker; retain report as observation | Evidence that the threshold predicts a concrete missed failure better than semantic tests at lower total cost |
| Historical milestone receipt in every pull request | archive | A current product path still consumes the exact old contract |
| One real browser journey | retain/localize | It catches product integration failures not covered by lower tests and has bounded cost |
| Command identity and response-loss reconciliation | retain | Reproduced duplicate-Effect failure and low recurring cost |
| Exact authority binding | retain | Prevents one approval from authorizing another actor, action, or world state |
| Old Agent and Team debug APIs | delete or archive by default | A current operator, migration, or experiment uses them and no narrower offline tool is sufficient |
| Zero runtime dependencies as a rule | delete | A current dependency-free deployment property has measured value greater than local reimplementation cost |
| Fixed release version in source | delete | No capability; package metadata and tag binding are narrower |
| Historical evaluation documents in active Context | archive | A current decision requires the derivation and cannot use a concise current summary |

## 3. Cross-repository implications

### Ordivon Computing

- Core principles and portfolio mechanisms must re-audit themselves.
- Completed studies remain references only when they still compress useful understanding; otherwise Git history is sufficient.
- Protocol objects require current cross-boundary consumers, not conceptual elegance.

### Ordivon Host and Harness

- Compatibility paths do not remain active merely to enable hypothetical equal-budget comparison.
- Generic lifecycle objects must prove more net deletion than local adapters and provider-native mechanisms.
- Model limitations that motivated a guard must name the deletion trigger as models and Harnesses improve.

### Ordivon Runtime

- Execution and recovery invariants remain where real response loss, cancellation, isolation, and process failure require them.
- Convenience wrappers, duplicate status objects, and broad preflight gates need current operating evidence.

### Ordivon Game

- Product experience is not subordinated to infrastructure evidence rituals.
- Game-specific content may remain for intrinsic value, while permanent engines, compatibility paths, protocols, and gates face the retention audit.
- A second materially different world is still required before Station Zero mechanisms become shared architecture.

### Ordivon World, Security, and Web

- Provider adapters, attack/evaluation structures, publication pipelines, graph models, and content taxonomies remain local unless a current consumer and failure justify promotion.
- Historical research volume does not require active nodes, routes, documents, or UI surfaces.

## 4. Risks of aggressive deletion

The inversion can fail if applied without consequence awareness.

### Repeated rediscovery

If a compact structure repeatedly returns because the same failure recurs and reconstruction consumes more attention than maintenance, it may pass retention audit.

### External compatibility breakage

A current public consumer, legal obligation, participant expectation, or stored-data format can make abrupt removal costly. The correct disposition may be localized compatibility with a declared migration horizon rather than immediate deletion.

### Destruction of unique evidence

Rare traces, participant-owned records, security evidence, and expensive experiments may be cheap to remove from active Context but expensive or impossible to recreate. Archive them under the appropriate authority.

### Hidden coupling

A consumer may be real but unobserved. Before deleting a consequence-bearing public boundary, inspect actual calls, deployments, and data. The presumption changes the decision burden; it does not justify blindness.

### Creative impoverishment

Applying infrastructure minimalism to characters, spaces, stories, rituals, visual detail, or playful mechanics can optimize a Game into an empty machine. Experiential judgment remains a separate admission path.

## 5. Falsifiers

The strong form of the inversion should be narrowed if repeated evidence shows that:

1. active removal causes costly rediscovery more often than it reduces maintenance and Context burden;
2. Git/archive restoration is materially slower or less reliable than retaining a narrow dormant implementation;
3. current consumers are systematically impossible to observe before removal;
4. compatibility breakage creates greater unrecoverable loss than the active burden it removed;
5. audit effort itself becomes a new recurring bureaucracy greater than the structures it deletes;
6. participants lose meaningful creative or operational capability because “current consumer” was interpreted too narrowly.

The response to such evidence is not a return to historical legitimacy. It is to localize retention where the recurring failure is demonstrated.

## 6. Final operational rule

```text
proposed or existing persistent structure
→ default: outside the active system
→ rescue only through current capability, concrete failure, narrow necessity, and positive recurring net value
→ give the retained form a review horizon
→ preserve learning separately from active compatibility
```

Deletion is the default disposition. Retention is a current, revisable judgment.
