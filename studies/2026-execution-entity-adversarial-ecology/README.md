# Execution-Entity Security and Adversarial Ecology

Status: completed reference study; `research/portfolio.json` owns any reactivation

## Purpose

This study broadens the unit of Ordivon Security research from one software
sample or one intelligent Agent to any **execution entity** that can produce
world effects, acquire resources, delegate authority, create descendants,
coordinate with peers, adapt to opposition, or persist across replacement.

The central question is:

> What minimum concepts and experiments are required to evaluate software,
> Agents, descendants, populations, organizations, and Campaigns as related
> execution entities without turning Ordivon into a universal ontology,
> antivirus product, cyber range, or security control plane?

## Core conclusion

The durable research object is not the file and not automatically the Agent. It
is the attributable relation among:

```text
Artifact
  → Execution Entity
  → Lineage
  → Population
  → Organization
  → Campaign
  → Ecosystem
```

Each level is conditional. A normal executable may require only Artifact and
single-Run evidence. An Agent that creates another Agent may require lineage and
authority inheritance. A self-propagating family may require population and
spread measurements. A coordinated adaptive group may require organization and
Campaign analysis. The higher levels must not be instantiated when lower-level
records are sufficient.

The study integrates nine mature bodies of knowledge:

- program analysis and malware research;
- game theory and security games;
- strategic and military theory;
- mathematical epidemiology;
- ecology and evolutionary dynamics;
- control theory and safety invariance;
- cyber-resilience engineering;
- organization and distributed-systems theory;
- AI-Agent security, hijacking, identity, and replication evaluation.

None of these disciplines independently supplies a complete model for a
language-capable, tool-using entity that can create descendants and reason about
its observers. Together they provide stronger baselines than an invented
Ordivon ontology.

## Relationship to current Ordivon Security

At revision `e37cc70dfddc0c7135d4661da7befed57be6e436`, Ordivon Security has two
implemented research profiles:

```text
Evaluation Trial
  one exact Sample under one exact authorized Environment

Contest
  multiple goal-bearing Actors under asymmetric observation and active conflict
```

Evaluation Trial already binds Sample, Authority, Environment, Guardian,
Observation, residual closure, Findings, and evidence. Contest already binds
Actors, action admission, Range truth, partial observations, outcomes, and
replay. The new study does not replace either path. It asks which additional
facts become irreducible when an evaluated subject can delegate, reproduce,
migrate, organize, or change the population being evaluated.

The bound implementation observation is retained in
[`research/evidence/observations/security-execution-entity-foundation-20260805.md`](../../research/evidence/observations/security-execution-entity-foundation-20260805.md).

## Claim boundary

This study does not claim that Ordivon has executed or reversed unknown
malware, implemented Agent replication, observed a malicious Agent population,
or demonstrated a general execution-entity protocol. It does not authorize
testing against unrelated systems. It produces a comparative research frame and
an experiment sequence for deciding whether any shared responsibility exists.

The strongest allowed conclusion is:

> Software Evaluation, Agent evaluation, lineage analysis, propagation studies,
> Contests, and Campaigns may share a compact identity-and-evidence relation, but
> that relation must be earned by at least two materially different workloads.
