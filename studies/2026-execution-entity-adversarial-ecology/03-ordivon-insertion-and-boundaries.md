# Ordivon Insertion and Repository Boundaries

## 1. Insertion thesis

Execution-entity research belongs in Ordivon Computing because it tests whether
several product-local workloads expose one compact cross-project responsibility.
It does not justify placing Security between every Agent and every action.

The candidate composition is:

```text
Artifact and configuration
        ↓
Host or Harness cognition and delegation
        ↓
Runtime / World / provider execution
        ↓
component-native observations and truth
        ↓
Security Evaluation or Contest interpretation
        ↓
Computing comparison, falsifier, and promotion decision
```

## 2. Responsibility matrix

| Concern | Natural owner | Security/Computing relation |
|---|---|---|
| static binary, script, package, model, or image analysis | mature external tools | Security consumes evidence; Ordivon does not rebuild analyzers |
| model loop, Context, Tool correction, Provider use | Harness | supplies exact cognition and Tool-use identity |
| Goal, Task, participants, durable continuation | Host | supplies objective, delegation, and replacement facts |
| process, Workspace, Job, Artifact, terminal and residual facts | Runtime | owns trusted-local physical execution facts, not adversarial meaning |
| task-to-provider interaction and external response identity | World or provider adapter | owns external interaction receipts and rebinding facts |
| simulated World, rules, hidden state, replay | Game or mature Range | supplies authoritative world semantics |
| disposable hostile-code machine, snapshot, egress enforcement | mature sandbox or hypervisor | remains outside current Runtime and Security implementations |
| Sample, Evaluation Spec, Guardian/Observer distinction, Finding | Security | owns software-evaluation semantics |
| Actor, Contest, opponent, strategic outcome | Security | owns adversarial-domain semantics |
| cross-domain identity, lineage, population, and promotion hypothesis | Computing research | tests whether any relation is reusable |

## 3. Current profile mapping

### Evaluation Trial

```text
Evaluation Trial
= single-subject authorized assessment profile
```

It binds one exact Sample and Environment. A future dynamic backend may add
static analysis, reverse engineering, runtime behavior, network evidence, and
residual verification. It should not automatically gain population or Campaign
state.

### Contest

```text
Contest
= multi-subject active-opposition profile
```

It binds independently controlled Actors, asymmetric observations, Range truth,
action admission, simultaneous semantics, and outcome evidence. It should not
require Artifact lineage unless subject derivation changes the experiment.

### Future Lineage Profile

```text
Lineage Profile
= parent-child, clone, generated Tool, delegated Agent, mutation, or replacement
```

This profile becomes justified when responsibility, authority, or control cannot
be reconstructed from current Runtime, Host, Harness, and Artifact references.

### Future Propagation Profile

```text
Propagation Profile
= population distribution, topology, spread, quarantine, recovery, and mutation
```

This profile becomes justified when aggregate spread and variant composition
change prediction or intervention.

## 4. Ordivon Security

Security should own:

- authorized evaluation and Contest semantics;
- which subject or actor is being evaluated;
- adversarial information boundaries;
- domain action admission;
- Guardian and evaluator policies;
- Findings and bounded dispositions;
- strategic, propagation, organization, and evaluator hypotheses;
- evidence requirements for a specific claim.

Security should not own:

- a hypervisor or container runtime;
- antivirus engines, reverse engineering, fuzzing, or forensics implementations;
- a general Agent loop;
- Provider secrets and retry policy;
- generic process lineage for all applications;
- a universal identity, IAM, graph, or event platform;
- organization semantics for non-adversarial workloads without second-consumer
  evidence.

## 5. Ordivon Computing

Computing owns:

- the comparative study;
- durable cross-project questions;
- classical baselines and null hypotheses;
- relations among Security, Verify, Adapt, Organization, Host, Harness, Runtime,
  Game, and World research;
- promotion and deletion decisions for any proposed shared responsibility.

Computing should not implement the Security workload or copy product truth.

## 6. Host and Harness

A model is not the complete Agent. The evaluated Agent subject may bind:

```text
model
+ Harness or delegated Harness
+ system and task instructions
+ Context selection
+ Tool catalog and grants
+ memory or continuation state
+ Provider configuration
+ authority and environment
```

Harness owns the inference and Tool loop. Host owns durable Goal, Task,
participant, and continuation relations. Security consumes exact identity and
behavioral evidence. A future child Agent must appear through actual Host,
Harness, Runtime, or provider facts, not a model's self-report.

## 7. Runtime

Runtime owns trusted-local execution facts and must retain its current boundary.
The existing `contained_local` profile is not hostile-code isolation. Unknown
software should not be executed through ordinary Runtime merely because
Evaluation Trial exists.

Runtime may later supply:

- parent and process identity;
- generated Artifact identity;
- resource usage;
- cancellation and terminal facts;
- residual classification;
- a request to an external disposable-machine provider.

Runtime should not infer malicious intent, strategic objective, population, or
Campaign outcome.

## 8. World, Game, and external Ranges

World binds external interactions and responses when they are not ordinary local
execution. Game and mature cyber ranges supply designed world state,
observations, rules, and replay. A sandbox or hypervisor supplies hostile-code
isolation.

The same high-level Security question may run across:

```text
static analyzer
fixture backend
simulated Range
local disposable VM
remote controlled Range
Agent Tool environment
```

The substrate identity must be bound; semantic equivalence must be tested rather
than assumed.

## 9. Verify and evaluator research

`ANC-VERIFY-001` owns general repeated evaluation, replay, trajectory evidence,
and evaluator comparison. Execution-entity research feeds new requirements into
Verify only when they generalize beyond Security:

- lineage-aware replay;
- descendant and parent attribution;
- evaluator visibility into generated entities;
- repeated hijacking attempts;
- held-out populations;
- evidence that survives subject replacement.

Security retains adversarial meaning and domain dispositions.

## 10. Adaptation and post-training

`ANC-ADAPT-001` may consume evidence only after improvement transfers across
held-out subjects, opponents, populations, and evaluators. Coevolution against a
single detector or opponent can select for evaluator exploitation rather than
real capability.

No training or self-improvement loop is implied by this study.

## 11. Organization

`ANC-ORG-001` asks whether plural-intelligence organization requires more than
ordinary Task and participant relations. Execution-entity research supplies a
hard case:

- a parent delegates to children;
- children have partial authority and information;
- one child is compromised or drifts;
- the parent is removed;
- the organization must revoke, replace, or reorganize;
- responsibility and evidence must remain attributable.

If Host-local relations express this case, no shared Organization protocol is
needed.

## 12. Repository admission test

A new implementation belongs in `ordivon-security` only if most answers are yes:

1. Is there an authorized Evaluation or active adversarial Contest?
2. Does identity, authority, lineage, propagation, opponent, organization, or
   evaluator state affect the claim?
3. Is the fact absent from the natural owner and mature tools?
4. Does the distinction change prediction, control, recovery, transfer, or
   evidence validity?
5. Is there a simpler baseline and deletion test?
6. Can the feature remain profile-local rather than universal?

A shared Computing/Core proposal additionally requires:

1. two materially different workload families;
2. a reproduced failure without the relation;
3. explicit natural ownership;
4. measured net benefit;
5. stable semantics under replacement;
6. a deletion path.

## 13. Immediate architectural decision

Do not rename current Evaluation Trial objects or Contest objects. Do not create
an `ExecutionEntityService`. Do not build a universal lineage database.

The immediate durable outputs are only:

- this study;
- `ANC-SECURITY-007`;
- an exact observation of current Security facts;
- a future experiment contract when a real lineage or propagation workload is
  admitted.
